PHP: Function, Scope, Parameter và Return

Mục lục← Ngày 13Ngày 15 →

Mục tiêu và chuẩn bị

Thiết kế hàm nhỏ có kiểu tham số và kiểu trả về; hiểu phạm vi biến, giá trị mặc định, tham trị và tham chiếu; kiểm thử trường hợp biên.

Lưu mỗi ví dụ vào một tệp .php riêng. Chạy php ten-tep.php; kiểm tra cú pháp bằng php -l ten-tep.php. Tự dự đoán kết quả trước khi chạy.

Từ bài toán đến hàm

Hàm gom một nhiệm vụ vào đơn vị có tên. Tham số là biến trong định nghĩa; đối số là giá trị truyền khi gọi. Hàm có thể được gọi nhiều lần với dữ liệu khác nhau.

<?php
function square(int $n): int {
    return $n * $n;
}
echo square(4); // 16

Kiểu int phía sau dấu hai chấm là kiểu giá trị trả về. Lưu đoạn code vào square.php và chạy php square.php.

Return khác echo

return gửi kết quả về nơi gọi và kết thúc hàm; echo hiển thị nội dung. Tách tính toán khỏi hiển thị giúp dùng lại hàm trong CLI, web và test.

<?php
function total(float $a, float $b): float {
    return $a + $b;
}
$result = total(3, 4);
echo $result; // 7

Không thể lấy kết quả tính toán từ một hàm chỉ echo nếu hàm không return. Một hàm không khai báo giá trị trả về tường minh sẽ trả null.

Kiểu dữ liệu và strict types

Type declaration giúp mô tả hợp đồng của hàm. declare(strict_types=1) áp dụng chế độ kiểm tra nghiêm ngặt với các lời gọi hàm từ tệp khai báo; vẫn cần kiểm tra các quy tắc nghiệp vụ như khoảng giá trị.

<?php
declare(strict_types=1);
function average(float $a, float $b): float {
    return ($a + $b) / 2;
}
var_dump(average(8, 6)); // float(7)

Đưa declare ngay sau thẻ mở PHP. Đừng nhầm type hint với validation đầy đủ dữ liệu người dùng.

Tham số mặc định và phạm vi

Giá trị mặc định được dùng khi không truyền đối số. Biến cục bộ khai báo trong hàm không tự xuất hiện ngoài hàm; ưu tiên truyền giá trị qua tham số thay vì dựa vào biến toàn cục.

<?php
function greeting(string $name = "bạn"): string {
    $prefix = "Xin chào ";
    return $prefix . $name;
}
echo greeting() . PHP_EOL; // Xin chào bạn
echo greeting("An"); // Xin chào An

Không tham chiếu $prefix bên ngoài hàm vì đó là biến cục bộ.

Tham trị và tham chiếu

Với giá trị số, hàm nhận bản sao theo mặc định. Ký hiệu & trước tham số cho phép hàm thay đổi biến của bên gọi; nên dùng khi việc thay đổi này là rõ ràng, cần thiết và được tài liệu hóa.

<?php
function addOne(int $n): void { $n++; }
function addOneInPlace(int &$n): void { $n++; }
$value = 5;
addOne($value); echo $value . PHP_EOL; // 5
addOneInPlace($value); echo $value; // 6

Hàm void không trả về giá trị sử dụng được. Tham chiếu cần nhận biến có thể thay đổi, không truyền trực tiếp biểu thức như 5 + 1.

Phân tích số nguyên tố và dữ liệu biên

Số nguyên tố là số nguyên lớn hơn 1 và chỉ có hai ước dương. Nếu số hợp số có ước lớn hơn căn bậc hai, nó cũng có một ước không lớn hơn căn bậc hai; do đó chỉ cần thử tới giới hạn này.

<?php
function isPrime(int $n): bool {
    if ($n < 2) return false;
    for ($i = 2; $i <= intdiv($n, $i); $i++) {
        if ($n % $i === 0) return false;
    }
    return true;
}
var_dump(isPrime(2), isPrime(9), isPrime(1));
// true, false, false

intdiv($n, $i) là cách kiểm tra giới hạn mà không nhân $i * $i; test thêm số âm và số chính phương như 49.

Viết test nhỏ cho hàm

Một phép kiểm thử so sánh kết quả thực tế với giá trị mong đợi và báo lỗi dễ hiểu. Test cả dữ liệu bình thường, biên và sai; không dùng assert như cơ chế validation dữ liệu người dùng.

<?php
function double(int $n): int { return $n * 2; }
$tests = [[2, 4], [0, 0], [-3, -6]];
foreach ($tests as [$input, $expected]) {
    if (double($input) !== $expected) {
        throw new RuntimeException("Kiểm thử thất bại: $input");
    }
}
echo "Đạt 3 trường hợp";

Tạo tệp test riêng và dùng require_once để nạp helpers.php. Tên hàm trong cùng chương trình không được khai báo trùng.

Bài tập theo lộ trình

  1. Tạo helpers.php với 10 hàm theo lộ trình: isPrime, calcAverage, formatCurrency, slugify, maskEmail, findMax, filterEven, countWords, validatePhone và calcAge; xác định rõ đầu vào rỗng, dữ liệu Unicode và giá trị không hợp lệ.
  2. Viết test_helpers.php thử tối thiểu hai bộ dữ liệu cho mỗi hàm; ghi rõ kết quả mong đợi. Với ngày sinh, kiểm tra ngày không hợp lệ và ngày trong tương lai.
  3. Thực hành tham số mặc định, phạm vi cục bộ, tham trị và tham chiếu; giải thích khi nào thay đổi ảnh hưởng biến bên gọi.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
