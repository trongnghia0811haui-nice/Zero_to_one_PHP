Thiết kế JSON nhất quán, giới hạn trường dữ liệu, cấu hình xác thực API phù hợp phiên bản Laravel và kiểm thử quyền trên các endpoint.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Route API và hợp đồng

API route mô tả method, đường dẫn, xác thực, request và response. Các phiên bản Laravel mới có thể không tạo routes/api.php mặc định; dùng hướng dẫn của phiên bản để cài tính năng API khi cần.

GET /api/students → danh sách có phân trang
GET /api/students/1 → chi tiết
POST /api/students → tạo mới

Xác định status 200/201/401/403/404/422 theo hợp đồng. Không để dữ liệu của người dùng khác lọt vào danh sách hoặc chi tiết.

API Resource

Resource định dạng dữ liệu trả về, giúp chỉ chọn các trường cần công bố. Không xuất password, remember_token hay thông tin nội bộ.

<?php
// Bên trong StudentResource::toArray(Request $request):
return [
    "id" => $this->id,
    "name" => $this->name,
    "email" => $this->email,
    "classroom" => $this->whenLoaded("classroom"),
];

Đoạn này nằm trong JsonResource. Việc có nên công bố email và dữ liệu lớp phụ thuộc quyền và hợp đồng API; có thể dùng resource riêng cho dữ liệu lồng nhau.

Collection và phân trang

Resource collection có thể giữ metadata phân trang khi nhận paginator. Dùng eager loading để tránh N+1 và giới hạn kết quả theo quyền user trước khi paginate.

<?php
// Trong API controller, sau khi áp dụng phạm vi truy cập.
$students = Student::with("classroom")->orderBy("id")->paginate(10);
return StudentResource::collection($students);

Đây là đoạn minh họa cần import model/resource. Laravel có thể thêm cấu trúc data, links và meta tùy cách cấu hình resource và phiên bản.

Sanctum và token

Sanctum hỗ trợ một số kiểu xác thực phù hợp ứng dụng Laravel. Personal access token cần được lưu và truyền an toàn, phân quyền theo khả năng cần thiết; không ghi token vào repo, log hay URL.

Authorization: Bearer YOUR_ACCESS_TOKEN
Accept: application/json

Đây chỉ là dạng header với placeholder, không phải token thật. Cài đặt Sanctum, middleware và route theo tài liệu phiên bản Laravel đang dùng.

Tạo token sau khi xác thực

Chỉ tạo token sau khi credentials hợp lệ và áp dụng rate limiting; token trả ra một lần cho client và phải được bảo vệ. Đặt tên, khả năng và thời hạn phù hợp, thu hồi khi logout.

<?php
// Trong controller, sau khi xác thực user và xác định abilities.
$token = $user->createToken("api-client", ["students:read"]);
return response()->json(["token" => $token->plainTextToken]);

Cần model user và Sanctum được cấu hình. Tuyệt đối không ghi plainTextToken vào log hoặc tài liệu công khai.

Bảo vệ route và quyền tài nguyên

auth:sanctum xác thực danh tính qua cấu hình tương ứng. Policy, scope dữ liệu và ability kiểm soát quyền hành động và quyền truy cập vào từng bản ghi.

<?php
use Illuminate\Support\Facades\Route;

Route::middleware("auth:sanctum")->group(function () {
    Route::post("/students", [StudentController::class, "store"]);
});

Đoạn route API cần import controller và cấu hình Sanctum. Xác thực hợp lệ không có nghĩa user được phép sửa mọi sinh viên.

Kiểm thử các nhánh

Kiểm tra thiếu token, token sai, user thiếu quyền, validation lỗi, ID không tồn tại, phân trang và dữ liệu nhạy cảm không xuất hiện. Kiểm tra thu hồi token và truy cập lại.

Không token → 401 theo hợp đồng
Có token nhưng không đủ quyền → 403
Dữ liệu sai → 422
Tạo thành công → 201

Mỗi tình huống cần test độc lập trên môi trường thử nghiệm; không dùng token production trong Postman Collection.

Bài tập theo lộ trình

  1. Cấu hình routes/api.php và Sanctum theo phiên bản Laravel; tạo API StudentController, Resource/Collection và phân trang theo quyền.
  2. Trả JSON có các trường được phép, format ngày phù hợp và dữ liệu classroom; kiểm tra metadata phân trang và tránh N+1.
  3. Tạo API login, bảo vệ route ghi, kiểm tra token, quyền, validation, tài nguyên thiếu và thu hồi khi logout.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
