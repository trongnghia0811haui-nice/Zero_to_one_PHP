Authentication và authorization

Authentication trả lời người dùng là ai; authorization quyết định họ có quyền thực hiện hành động trên tài nguyên cụ thể không. Đăng nhập thành công không đồng nghĩa được xem hoặc sửa tất cả dữ liệu.

Request → xác thực → xác định tài nguyên → kiểm tra quyền → xử lý

Ẩn nút chỉ cải thiện giao diện; endpoint vẫn phải kiểm tra quyền ở server.

Đăng nhập và session

Auth::attempt kiểm tra credentials theo cấu hình authentication. Sau đăng nhập, regenerate session để giảm nguy cơ session fixation; không ghi mật khẩu vào log hoặc response.

<?php
// Trong controller Laravel; $credentials đã validate.
if (\Illuminate\Support\Facades\Auth::attempt($credentials)) {
    $request->session()->regenerate();
    return redirect()->intended("/dashboard");
}
return back()->withErrors(["email" => "Thông tin đăng nhập không đúng."]);

Thông báo chung giúp tránh tiết lộ tài khoản tồn tại. Cần giới hạn thử đăng nhập, CSRF protection và cấu hình cookie an toàn.

Hash mật khẩu và đăng xuất

Dùng Hash::make để tạo hash mật khẩu, không tự dùng mã hóa đảo ngược hoặc lưu plaintext. Khi logout, vô hiệu session và regenerate CSRF token theo quy trình Laravel.

<?php
// Trong controller Laravel sau validation:
$hash = \Illuminate\Support\Facades\Hash::make($password);
// Khi logout:
\Illuminate\Support\Facades\Auth::logout();
$request->session()->invalidate();
$request->session()->regenerateToken();

Ví dụ chứa hai tình huống riêng, không đặt liên tiếp thành luồng đăng ký/đăng xuất thật. Không lưu hoặc in $password.

Middleware

Middleware bao quanh request và có thể từ chối hoặc chuyển hướng khi chưa đáp ứng điều kiện. Bảo vệ route bằng auth; role middleware cần xử lý user null và vai trò không hợp lệ.

<?php
use Illuminate\Support\Facades\Route;

Route::middleware(["auth"])->group(function () {
    Route::get("/dashboard", fn () => "Dashboard");
});

Middleware auth chỉ xác thực; vẫn cần authorization cho từng tài nguyên. Cách đăng ký alias middleware thay đổi theo phiên bản Laravel, xem tài liệu phiên bản của dự án.

Policy cho tài nguyên

Policy gom quy tắc quyền theo model. Ví dụ kiểm tra quyền chỉnh sửa dựa trên owner_id; cấu trúc dữ liệu và vai trò thật của dự án có thể khác.

<?php
// Bên trong policy, giả sử Student có owner_id và User có id.
public function update(User $user, Student $student): bool {
    return $student->owner_id === $user->id;
}

ID có thể cần được cast nhất quán theo model. Với schema không có owner_id, thay bằng quy tắc phù hợp thay vì giả định cột tồn tại.

Kiểm tra quyền ở controller và view

Controller phải kiểm tra quyền trước khi thao tác; Blade @can có thể ẩn nút nếu không có quyền nhưng không phải ranh giới bảo mật duy nhất.

@can('update', $student)
  <a href="{{ route('students.edit', $student->id) }}">Sửa</a>
@endcan

Trong controller dùng Gate::authorize("update", $student) hoặc cơ chế tương đương theo phiên bản; thử gửi request trực tiếp để xác nhận server từ chối.

Kiểm thử quyền và trạng thái

Tạo user có quyền và không có quyền; thử tài nguyên của người khác, request chưa đăng nhập, logout và giới hạn đăng nhập. Kiểm tra status và dữ liệu không bị thay đổi.

Chưa đăng nhập → redirect hoặc 401 theo hợp đồng
Đã đăng nhập không đủ quyền → 403
Có quyền + dữ liệu hợp lệ → xử lý thành công

Không chỉ kiểm tra nút bị ẩn. Với API, thống nhất response 401/403 và không để lộ bí mật trong log.

Bài tập theo lộ trình

  1. Thực hiện đăng ký, đăng nhập, đăng xuất an toàn bằng Auth/Hash hoặc giải pháp chính thức tương thích phiên bản; kiểm tra session và CSRF.
  2. Tạo middleware role admin theo hướng dẫn phiên bản Laravel và StudentPolicy; áp dụng ở server cho các thao tác thêm/sửa/xóa.
  3. Test user thường, admin và tài nguyên của người khác: request trực tiếp, 403, logout và dữ liệu không đổi khi bị từ chối.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
