Mục tiêu và chuẩn bị

Rà soát trải nghiệm ở các trạng thái, tài liệu hóa dự án và tự cài lại bản clone để xác nhận hướng dẫn có thể lặp lại.

Chuẩn bị bản ghi chú, sơ đồ và dự án thử nghiệm. Ví dụ minh họa phải được điều chỉnh theo yêu cầu và môi trường thực tế.

MVP có thể sử dụng và kiểm chứng

Một MVP cần hoàn thành luồng cốt lõi, dữ liệu nhất quán, bảo vệ quyền và chỉ dẫn vận hành cơ bản. Ưu tiên sửa lỗi cản trở người dùng trước các thay đổi trang trí.

Đăng nhập → project → task → giao việc → theo dõi trạng thái

Đối chiếu từng tiêu chí của yêu cầu, kiểm tra cả tài khoản không có quyền.

Responsive và trạng thái giao diện

Kiểm tra desktop, tablet, mobile; chú ý overflow bảng, vùng chạm, nhãn input và focus bàn phím. Trang cần trạng thái loading, rỗng, thành công và lỗi khi chúng xảy ra.

Danh sách rỗng → giải thích và hành động phù hợp
Lỗi tải → thông báo và cách thử lại
Lưu thành công → phản hồi rõ ràng

Không dùng màu làm tín hiệu duy nhất; không tiết lộ lỗi SQL hoặc stack trace cho người dùng.

Trang lỗi và quyền

Tạo trang 403/404 phù hợp thương hiệu và ngôn ngữ; không tiết lộ dữ liệu nhạy cảm. Kiểm tra status HTTP thực tế, không chỉ hiển thị chữ lỗi với status 200.

403 → không đủ quyền
404 → không tìm thấy theo chính sách

Giao diện báo lỗi không thay thế policy/server. Nêu bước tiếp theo có ích cho người dùng.

README có thể thực hiện

README nên nêu yêu cầu phiên bản, cài đặt, cấu hình .env.example, migration/seed trên DB test, chạy ứng dụng, test, chức năng và cấu trúc API. Lệnh phải khớp phiên bản và được kiểm chứng.

Yêu cầu → Cài đặt → Cấu hình → Chạy → Test → API → Hạn chế

Không đưa mật khẩu thật, APP_KEY, token hoặc dữ liệu cá nhân vào README hay ảnh chụp.

Ảnh màn hình và ERD

Ảnh giúp người xem hiểu sản phẩm; dùng dữ liệu demo không nhạy cảm. ERD cần khớp migration và chỉ rõ quan hệ, khóa quan trọng.

Đây là đường dẫn đề xuất; tạo ảnh thực tế trong dự án của bạn và kiểm tra không lộ email, token hoặc dữ liệu thật.

Postman và API

Collection nên dùng biến môi trường, mô tả xác thực và trường hợp lỗi. Không export biến chứa token thật; test trên môi trường thử nghiệm.

{{base_url}}/api/projects
Authorization: Bearer {{access_token}}

Đây là placeholder. Cần bảo vệ giá trị access_token và không commit environment chứa secret.

Tự clone và kiểm tra lại

Clone vào thư mục mới, làm theo README như người chưa tham gia dự án; dùng DB riêng và ghi lại bước không rõ hoặc thất bại. Chỉ thực hiện Git push/public hoặc deploy nếu được yêu cầu.

Clone riêng → cấu hình ví dụ → cài phụ thuộc → migrate test → chạy → test

Không xóa workspace đang làm hoặc ghi đè cấu hình cá nhân. Chỉ chạy lệnh phá hủy với database test đã xác nhận.

Kiểm tra cuối MVP

Đối chiếu chức năng, quyền, lỗi rỗng, validation, API, test, README và trạng thái Git. Không khẳng định production-ready nếu chỉ kiểm tra MVP cục bộ.

Chạy luồng chính + nhánh lỗi → kiểm tra bảo mật cơ bản → ghi hạn chế còn lại

Nếu test hoặc tích hợp chưa chạy được, tài liệu cần nói rõ thay vì mô tả như đã hoạt động.

Bài tập theo lộ trình

  1. Hoàn thiện responsive, empty state và trang 403/404; kiểm tra bàn phím và status thực tế.
  2. Chụp ảnh an toàn, tạo ERD và README gồm cài đặt, tài khoản demo, API và Postman collection không chứa secret.
  3. Clone dự án sang thư mục mới, làm theo README với DB test và ghi lại các bước cần sửa; kiểm tra lại test.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.

Tham khảo MySQL Manual và PHP Manual, chọn đúng phiên bản đang dùng.
