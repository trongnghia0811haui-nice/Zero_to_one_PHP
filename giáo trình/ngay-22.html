MySQL: SELECT, INSERT, UPDATE và DELETE

Mục tiêu và chuẩn bị

Thực hành CRUD bằng SQL trên database sinh viên, dùng điều kiện và phân trang, đồng thời hiểu tác động của ràng buộc và các thao tác ghi.

Thực hành trên cơ sở dữ liệu MySQL thử nghiệm riêng, không dùng dữ liệu quan trọng. Chuẩn bị schema từ bài trước khi chạy các truy vấn liên quan.

Chuẩn bị dữ liệu và an toàn

Sử dụng schema student_management của Ngày 21 trên database thử nghiệm. Trước mỗi lệnh ghi, xác định bảng và điều kiện; SELECT trước UPDATE/DELETE giúp xem phạm vi dự kiến nhưng không thay thế transaction hoặc kiểm soát đồng thời.

USE student_management;
SELECT DATABASE();
SELECT id, name, email FROM students ORDER BY id;

Những ví dụ dùng ID giả định; hãy thay bằng ID thực tế trong dữ liệu mẫu của bạn. Không chạy DELETE hay UPDATE trên dữ liệu quan trọng khi chưa hiểu tác động.

SELECT và WHERE

SELECT chọn các cột; WHERE lọc dòng. Dùng danh sách cột rõ ràng giúp người đọc hiểu dữ liệu cần lấy. Kết quả không có thứ tự được đảm bảo nếu thiếu ORDER BY.

SELECT id, name, email
FROM students
WHERE class_id = 1
ORDER BY name, id;

Khi hai tên giống nhau, id làm tiêu chí phụ để kết quả có thứ tự ổn định hơn.

INSERT tạo bản ghi

INSERT chỉ rõ tên cột và giá trị. Phải thỏa NOT NULL, UNIQUE và FOREIGN KEY. Câu ví dụ dùng email miền .test; thay class_id bằng ID lớp đã có.

INSERT INTO students (name, email, phone, class_id)
VALUES ('Lan', 'lan@example.test', '0900000001', 1),
       ('Minh', 'minh@example.test', NULL, 1);

Chạy lại cùng email có thể báo lỗi UNIQUE. Dữ liệu từ người dùng trong ứng dụng PHP phải truyền qua prepared statement, không nối trực tiếp vào SQL.

UPDATE có điều kiện

UPDATE thay đổi các dòng khớp WHERE. Quên WHERE sẽ tác động tất cả dòng; trước tiên kiểm tra điều kiện bằng SELECT và đảm bảo giá trị khóa chính xác.

SELECT id, email FROM students WHERE id = 1;
UPDATE students
SET email = 'an.moi@example.test'
WHERE id = 1;
SELECT id, email FROM students WHERE id = 1;

Ví dụ thay đổi dữ liệu: chỉ dùng bản thử nghiệm. Số dòng bị ảnh hưởng tùy giá trị và cài đặt; kiểm tra kết quả sau khi cập nhật.

DELETE và ràng buộc

DELETE xóa dòng khớp điều kiện; khóa ngoại và ON DELETE CASCADE có thể xóa thêm các dòng liên quan. Hãy hiểu schema, kiểm tra dữ liệu và có phương án khôi phục trước khi xóa.

SELECT id, student_id, subject_id, score
FROM scores WHERE id = 1;
DELETE FROM scores WHERE id = 1;

Không chạy nếu chưa xác định bản ghi thử cần xóa. Không dùng DELETE không có WHERE để dọn dữ liệu quan trọng.

LIKE, IN và BETWEEN

LIKE dùng mẫu, % thay chuỗi bất kỳ và _ thay một ký tự; IN kiểm tra thuộc tập; BETWEEN gồm cả hai đầu mút. Kết quả so sánh chuỗi phụ thuộc collation.

SELECT id, name FROM students WHERE name LIKE '%An%';
SELECT id, name FROM students WHERE class_id IN (1, 2);
SELECT id, score FROM scores WHERE score BETWEEN 8 AND 10;

Đây là ví dụ dữ liệu cố định. Khi đưa keyword từ người dùng vào ứng dụng, dùng tham số và thiết kế quy tắc xử lý ký tự wildcard.

LIMIT và OFFSET

LIMIT giới hạn số dòng; OFFSET bỏ qua một số dòng đầu. Dùng ORDER BY có tiêu chí phân biệt, chẳng hạn id, để phân trang có thứ tự xác định.

SELECT id, name FROM students
ORDER BY id
LIMIT 5 OFFSET 5;

Ví dụ lấy tối đa 5 dòng sau 5 dòng đầu. Khi dữ liệu đổi giữa các request, offset pagination vẫn có thể lặp hoặc bỏ sót bản ghi.

  2. Chèn class_id không tồn tại và email trùng trong dữ liệu thử nghiệm để quan sát ràng buộc; ghi lại lỗi và trạng thái dữ liệu.
  3. Với mọi lệnh UPDATE/DELETE, viết SELECT xem trước và kiểm tra lại sau thao tác; giải thích tác động của CASCADE nếu có.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
