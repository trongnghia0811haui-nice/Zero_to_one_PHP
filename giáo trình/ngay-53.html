Task Management: Search, Filter và Pagination

Mục tiêu và chuẩn bị

Xây dựng bộ lọc đa điều kiện có validation, giữ query string khi phân trang và kiểm tra N+1 với dữ liệu thực tế.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Xác định hợp đồng bộ lọc

Quy định keyword, status, priority, assignee, khoảng deadline, sort và mặc định. Validate kiểu, miền giá trị, độ dài; quyết định phạm vi tìm kiếm và cách xử lý giá trị rỗng.

GET /tasks?q=api&status=todo&page=2

Ví dụ chỉ mô tả URL. Người dùng vẫn phải được giới hạn vào các project và task có quyền truy cập.

Scope Eloquent

Local scope gom bộ lọc có thể tái sử dụng; nên nhận dữ liệu đã validate và không tự bỏ qua quyền. Đặt scope quyền riêng hoặc áp dụng trước scope filter.

<?php
// Trong model Task, đoạn minh họa tối giản.
public function scopeFilter($query, array $filters) {
    return $query->when($filters["status"] ?? null,
        fn ($q, $status) => $q->where("status", $status));
}

Chỉ là một điều kiện. Bài tập cần triển khai đầy đủ keyword, priority, assignee, deadline và sort, cùng validation.

Tìm từ khóa và nhóm điều kiện

Khi kết hợp name/title OR description với scope quyền, nhóm các điều kiện OR trong closure để tránh điều kiện OR làm rộng phạm vi dữ liệu ngoài ý muốn.

<?php
// Sau khi đã áp dụng $query theo quyền.
$query->where(function ($q) use ($keyword) {
    $q->where("title", "like", "%" . $keyword . "%")
      ->orWhere("description", "like", "%" . $keyword . "%");
});

Query builder bind giá trị; % và _ trong keyword vẫn là wildcard. Quy định tìm chính xác hay theo mẫu, và escape phù hợp nếu cần tìm ký tự literal.

Whitelist sắp xếp

Tên cột và chiều sắp xếp không thể an toàn hóa bằng value placeholder như dữ liệu thông thường. Ánh xạ input sang tập cột và chiều được phép, có giá trị mặc định.

Các cột cho phép: due_date, created_at, title
Chiều cho phép: asc, desc
Sai hoặc thiếu → dùng mặc định theo hợp đồng

Thêm id làm tiêu chí phụ để có thứ tự ổn định. Không nối thẳng tên cột user nhập vào SQL.

Phân trang và query string

paginate giới hạn kết quả; withQueryString giữ filter trong các liên kết trang. Đặt page size hợp lý, validate page và thử khi filter thay đổi làm số trang giảm.

<?php
// Sau khi query đã áp dụng quyền, filter và ORDER BY.
$tasks = $query->paginate(10)->withQueryString();

Offset pagination có thể lặp hoặc bỏ bản ghi khi dữ liệu thay đổi giữa các lần tải; cursor pagination là lựa chọn cần cân nhắc khi phù hợp.

Eager loading và withCount

with nạp quan hệ theo lô; withCount đếm quan hệ mà không cần tải mọi object. Kiểm tra tên quan hệ thực tế: task có assignees và project; project có tasks.

<?php
// Truy vấn task trong ứng dụng đã định nghĩa quan hệ.
$tasks = Task::with(["assignees", "project"])->paginate(10);
// Khi truy vấn project, có thể dùng Project::withCount("tasks").

Đo số query và xác minh kết quả. withCount("tasks") phải gọi trên model có quan hệ tasks, không mặc định áp lên model Task.

Kiểm thử kết hợp và biên

Kiểm thử từng điều kiện và các tổ hợp, khoảng ngày sai thứ tự, status không hợp lệ, keyword rỗng, kết quả không có dữ liệu, page quá lớn và user ngoài dự án.

User A không thuộc Project B + keyword khớp task B → không trả task B
Ngày bắt đầu sau ngày kết thúc → lỗi validation theo hợp đồng

Xác nhận query, response và trạng thái UI. Đo số query trên tập dữ liệu đại diện thay vì chỉ một dòng.

Bài tập theo lộ trình

  1. Viết scopeFilter cho keyword, status, priority, assignee, deadline và sort; validate từng trường và whitelist cột/chiều.
  2. Phân trang 10 dòng cho web/API, giữ query string; test không có kết quả, trang cuối và tham số sai.
  3. Dùng with assignees/project và withCount tasks trên đúng model; đo N+1 và kiểm tra không rò rỉ task ngoài phạm vi quyền.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
