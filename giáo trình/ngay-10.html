DOM, Event và Form Validation

Đưa dữ liệu JavaScript lên trang web và phản hồi thao tác của người dùng.

Mục lục← Ngày 09Ngày 11 →

1. Mục tiêu và chuẩn bị

Sau bài này, bạn có thể chọn phần tử, đọc dữ liệu form, xử lý sự kiện, hiển thị lỗi và thêm hoặc xóa dòng trong bảng. Bạn cũng sẽ biết lưu dữ liệu không nhạy cảm bằng localStorage và xử lý khi không đọc hoặc ghi được.

Chuẩn bị VS Code, trình duyệt và DevTools. Tạo thư mục riêng cho bài tập, mở trang qua máy chủ phát triển cục bộ như Live Server. Nhấn F12 → Console để xem thông báo lỗi. Đừng dùng mật khẩu thật khi thử nghiệm.

2. DOM — JavaScript nhìn thấy trang như thế nào?

Document Object Model (DOM) là biểu diễn tài liệu dưới dạng cây đối tượng. Trình duyệt tạo DOM từ HTML; JavaScript có thể chọn một phần tử và thay đổi văn bản, thuộc tính hoặc thêm phần tử con.

<h1 id="title">Danh sách sinh viên</h1>
<script>
  const title = document.querySelector('#title');
  title.textContent = 'Quản lý sinh viên';
</script>

querySelector trả phần tử khớp đầu tiên hoặc null nếu không tìm thấy. querySelectorAll trả danh sách các phần tử khớp; dùng forEach để duyệt. textContent đặt chữ thuần, tránh diễn giải dữ liệu người dùng thành HTML.

const title = document.querySelector('#missing');
if (title !== null) {
    title.textContent = 'Đã tìm thấy';
} else {
    console.log('Không tìm thấy phần tử');
}

Lỗi thường gặp: sai selector hoặc chạy script trước khi phần tử được tạo khiến biến nhận null. Đặt script cuối body hoặc dùng defer cho script bên ngoài.

3. Event — phản hồi tương tác

Sự kiện xảy ra khi người dùng nhấn nút, nhập chữ hoặc gửi form. addEventListener đăng ký hàm xử lý; sự kiện input phù hợp tìm kiếm khi nội dung thay đổi, còn submit bắt cả nhấn nút gửi và Enter trong form.

<button id="hello" type="button">Chào</button>
<p id="message"></p>
<script>
const button = document.querySelector('#hello');
const message = document.querySelector('#message');
button.addEventListener('click', function () {
    message.textContent = 'Xin chào!';
});
</script>

Ghi addEventListener('click', handler) thay vì handler(): cách sau gọi hàm ngay lúc đăng ký. Trong form, type="button" tránh gửi form ngoài ý muốn.

4. Xác thực form

HTML cung cấp required, type="email" và minlength. JavaScript có thể hiển thị lỗi phù hợp hơn, nhưng kiểm tra ở trình duyệt không thay thế kiểm tra ở server. preventDefault() chặn thao tác gửi mặc định khi muốn tự xử lý.

Ví dụ có thể tự chạy

Lưu nội dung sau thành validate.html, mở qua Live Server, thử để trống, nhập email sai và nhập dữ liệu hợp lệ. Đây là ví dụ giao diện, không gửi dữ liệu lên server.

<!doctype html>
<html lang="vi">
<meta charset="utf-8">
<title>Kiểm tra form</title>
<form id="student-form" novalidate>
  <label for="name">Họ tên</label>
  <input id="name" name="name" required aria-describedby="name-error">
  <span id="name-error" role="alert"></span>
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required aria-describedby="email-error">
  <span id="email-error" role="alert"></span>
  <label for="password">Mật khẩu</label>
  <input id="password" name="password" type="password" required minlength="6" aria-describedby="password-error">
  <span id="password-error" role="alert"></span>
  <button type="submit">Kiểm tra</button>
  <p id="status" role="status"></p>
</form>
<script>
const form = document.querySelector('#student-form');
const nameInput = document.querySelector('#name');
const email = document.querySelector('#email');
const password = document.querySelector('#password');
const status = document.querySelector('#status');
form.addEventListener('submit', (event) => {
    event.preventDefault();
    const nameError = nameInput.value.trim() ? '' : 'Hãy nhập họ tên.';
    const emailError = email.validity.valid ? '' : 'Hãy nhập email hợp lệ.';
    const passwordError = password.value.length >= 6 ? '' : 'Mật khẩu cần ít nhất 6 ký tự.';
    document.querySelector('#name-error').textContent = nameError;
    document.querySelector('#email-error').textContent = emailError;
    document.querySelector('#password-error').textContent = passwordError;
    status.textContent = nameError || emailError || passwordError
        ? 'Vui lòng sửa các trường có lỗi.' : 'Dữ liệu hợp lệ.';
});
</script>
</html>

novalidate tắt thông báo kiểm tra tự động của trình duyệt khi gửi để ví dụ tự hiển thị lỗi; thuộc tính validity vẫn được dùng để kiểm tra email. Khi làm bài, có thể thêm CSS cho thông báo lỗi màu đỏ.

5. Tạo và xóa dòng bảng an toàn

createElement tạo phần tử, append thêm phần tử vào cây DOM và remove xóa phần tử. Dùng textContent cho tên do người dùng nhập để nó được hiển thị như văn bản, không được hiểu là thẻ HTML.

// Giả sử tbody là phần tử <tbody> đã được chọn.
function addRow(tbody, student) {
    const row = document.createElement('tr');
    const nameCell = document.createElement('td');
    nameCell.textContent = student.name;
    const actionCell = document.createElement('td');
    const removeButton = document.createElement('button');
    removeButton.type = 'button';
    removeButton.textContent = 'Xóa';
    removeButton.addEventListener('click', () => row.remove());
    actionCell.append(removeButton);
    row.append(nameCell, actionCell);
    tbody.append(row);
}

Đoạn này chỉ thay đổi DOM. Nếu bạn có mảng sinh viên và localStorage, thao tác xóa còn phải cập nhật mảng và lưu lại; nếu không, dữ liệu cũ có thể xuất hiện lại sau khi tải trang.

6. localStorage và JSON

localStorage lưu chuỗi theo cặp khóa–giá trị trong trình duyệt. JSON.stringify chuyển dữ liệu thành chuỗi, JSON.parse đọc lại. Dữ liệu thuộc trình duyệt và phạm vi nguồn gốc của trang, không tự đồng bộ giữa thiết bị; đừng lưu mật khẩu hoặc dữ liệu nhạy cảm.

const key = 'day10-students';
const students = [{ id: 1, name: 'An' }];
try {
    localStorage.setItem(key, JSON.stringify(students));
    const stored = JSON.parse(localStorage.getItem(key) || '[]');
    console.log(stored); // [{ id: 1, name: 'An' }]
} catch (error) {
    console.error('Không thể đọc hoặc lưu dữ liệu:', error);
}

localStorage có thể bị chặn hoặc đầy và JSON cũ có thể hỏng. Khi đọc dữ liệu trong bài thật, cần kiểm tra cả cấu trúc, ví dụ dùng Array.isArray, rồi thông báo lỗi hoặc khôi phục an toàn; không giả định dữ liệu luôn hợp lệ.

7. Mini project cuối chặng

Mục tiêu: mở rộng form Ngày 03 thành trang quản lý sinh viên. Không lưu trường mật khẩu vào bảng hay localStorage.

  1. Chặn gửi mặc định và kiểm tra họ tên không rỗng, email đúng định dạng, mật khẩu ít nhất 6 ký tự; hiển thị lỗi đỏ ngay dưới từng ô.
  2. Khi hợp lệ, thêm một object chỉ chứa dữ liệu cần thiết vào mảng, hiển thị vào bảng và xóa nội dung form phù hợp.
  3. Thêm nút xóa cho từng sinh viên; cập nhật mảng, bảng và dữ liệu lưu.
  4. Bắt sự kiện input trên ô tìm kiếm; lọc tên không phân biệt chữ hoa/thường và hiển thị trạng thái không có kết quả.
  5. Lưu danh sách vào localStorage; tải lại và xử lý dữ liệu sai định dạng, quyền lưu bị chặn hoặc dữ liệu rỗng.

Gợi ý thứ tự: xử lý form → mảng dữ liệu → hàm render bảng → xóa → tìm kiếm → lưu và khôi phục. Tự làm từng bước và thử trước khi chuyển bước tiếp theo.

8. Lỗi thường gặp và tự kiểm tra

  • Chọn nhầm ID: kiểm tra giá trị trả về từ querySelector trước khi sử dụng.
  • Nhập tên chứa thẻ HTML: hiển thị bằng textContent, tránh nối vào innerHTML.
  • Đã xóa dòng nhưng tải lại xuất hiện: cập nhật dữ liệu và localStorage, không chỉ xóa DOM.
  • Form trông hợp lệ nhưng vẫn phải kiểm tra ở server khi có backend.
  • Kiểm tra bàn phím: Tab qua các trường, nhấn Enter gửi, thử thông báo lỗi và trường rỗng.

Nguồn tham khảo: DOM, Form validation, localStorage.
