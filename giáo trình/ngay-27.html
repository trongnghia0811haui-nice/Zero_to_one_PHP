PHP và MySQL: SQL Injection, Transaction, Validation

Mục lục← Ngày 26Ngày 28 →

Mục tiêu và chuẩn bị

Nhận diện SQL injection, sử dụng prepared statement, thiết kế transaction cho nhiều thao tác liên quan và xác thực dữ liệu ở ranh giới server.

Thực hành trên cơ sở dữ liệu MySQL thử nghiệm riêng, không dùng dữ liệu quan trọng. Chuẩn bị schema từ bài trước khi chạy các truy vấn liên quan.

SQL injection là gì?

SQL injection xảy ra khi đầu vào không đáng tin bị ghép thành cú pháp SQL và thay đổi ý nghĩa truy vấn. Chỉ thực hành minh họa trên dữ liệu thử nghiệm do bạn kiểm soát; không thử trên hệ thống người khác.

<?php
// Không dùng trong ứng dụng: nối dữ liệu vào câu SQL.
$unsafe = "SELECT * FROM students WHERE name = '" . "INPUT" . "'";
echo $unsafe;

Khi SQL và dữ liệu bị nhập chung, dấu nháy và toán tử có thể làm thay đổi cú pháp. Không chạy ví dụ nối chuỗi với dữ liệu thật.

Prepared statement bảo vệ giá trị

Truyền dữ liệu qua placeholder để driver phân biệt cấu trúc truy vấn và giá trị. Prepared statement không thay thế authorization, validation hay whitelist tên cột động.

<?php
// Giả sử $pdo là kết nối MySQL hợp lệ.
$stmt = $pdo->prepare("SELECT id, name FROM students WHERE name = :name");
$stmt->execute(["name" => $name]);
$rows = $stmt->fetchAll(PDO::FETCH_ASSOC);

Đoạn ví dụ cần $pdo và $name được chuẩn bị. Phương pháp này không dùng để chèn tên bảng hoặc cột trực tiếp vào SQL.

Transaction và tính nguyên tử

Transaction nhóm nhiều thao tác thành một đơn vị: commit khi tất cả thành công, rollback khi thất bại. Trên MySQL, dùng bảng hỗ trợ transaction như InnoDB; một số câu DDL có thể gây implicit commit.

<?php
// Giả sử $pdo được cấu hình ERRMODE_EXCEPTION và kết nối InnoDB.
$pdo->beginTransaction();
try {
    // Thực hiện các lệnh SQL liên quan.
    $pdo->commit();
} catch (Throwable $e) {
    if ($pdo->inTransaction()) $pdo->rollBack();
    throw $e;
}

Không nuốt exception. Đảm bảo tất cả lệnh cần nguyên tử chạy trên cùng kết nối và thuộc cùng transaction.

Ví dụ thiết kế nhập điểm nhiều môn

Trước khi ghi, kiểm tra từng điểm là số từ 0 đến 10 và môn học hợp lệ. Nếu bất kỳ dòng nào thất bại, rollback toàn bộ những dòng đã ghi trong transaction; kiểm tra ràng buộc UNIQUE ở database.

BEGIN;
INSERT INTO scores (student_id, subject_id, score) VALUES (1, 1, 8);
INSERT INTO scores (student_id, subject_id, score) VALUES (1, 2, 9);
COMMIT;

Chỉ chạy trên dữ liệu thử nghiệm với ID và cặp điểm chưa tồn tại. Đây là SQL minh họa transaction thành công; rollback khi lỗi được xử lý trong mã PDO.

Validation ở ranh giới

Kiểm tra kiểu trước khi ép kiểu, trường bắt buộc, khoảng giá trị và quyền của user. Tránh coi một chuỗi không hợp lệ như 0 chỉ vì ép kiểu; trả lỗi cụ thể cho từng trường.

<?php
$raw = "10.5";
$score = filter_var($raw, FILTER_VALIDATE_FLOAT);
if ($score === false || $score < 0 || $score > 10) {
    echo "Điểm không hợp lệ";
} else {
    echo "Điểm hợp lệ";
}
// Điểm không hợp lệ

filter_var có thể trả false; kiểm tra === false để không nhầm số 0 hợp lệ với false.

Lỗi và thông tin nhạy cảm

Ghi nhận lỗi với đủ ngữ cảnh nhưng không ghi password, token hoặc chuỗi kết nối. Trả thông báo phù hợp cho client; giữ stack trace và thông tin nội bộ ở nơi an toàn.

<?php
try {
    throw new RuntimeException("Lỗi giả lập");
} catch (RuntimeException $e) {
    echo "Không thể hoàn tất thao tác. Vui lòng thử lại.";
}

Ví dụ chỉ minh họa cách phân biệt thông báo người dùng; ứng dụng thực tế cần log có kiểm soát và chiến lược xử lý lỗi.

Kiểm thử rollback

Kiểm thử nên chứng minh trạng thái trước và sau transaction giống nhau khi một bước lỗi. Không chỉ kiểm tra exception; cần truy vấn lại database để kiểm tra không có dòng nào được ghi.

-- Ý tưởng kiểm thử trên DB thử nghiệm:
-- 1. Đếm các dòng trước transaction.
-- 2. Thử ghi 2 dòng, làm dòng thứ hai vi phạm UNIQUE.
-- 3. Rollback, đếm lại và xác nhận không có dòng mới.

Sử dụng dữ liệu và database dành riêng cho test. Hủy transaction dang dở và bảo đảm phép thử không xóa dữ liệu của người dùng.

Bài tập theo lộ trình

  1. Minh họa SQL injection bằng dữ liệu thử nghiệm cục bộ, sau đó sửa bằng PDO prepared statement và kiểm chứng cùng đầu vào không thay đổi cấu trúc SQL.
  2. Viết transaction nhập điểm nhiều môn; nếu có điểm ngoài 0–10 hoặc lỗi DB, rollback và kiểm tra không còn bản ghi nào mới.
  3. Viết Validator cho required, email, min, max, numeric; trả lỗi theo trường và thử dữ liệu thiếu, mảng thay cho chuỗi, 0 và giá trị biên.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
