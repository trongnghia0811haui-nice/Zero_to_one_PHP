PHP: Session, Cookie, Include và xử lý file

Mục lục← Ngày 17Ngày 19 →

Mục tiêu và chuẩn bị

Xây dựng trạng thái đăng nhập cơ bản, chia sẻ giao diện bằng các tệp PHP, đọc ghi JSON và ghi log mà không làm lộ dữ liệu nhạy cảm.

Lưu mỗi ví dụ vào một tệp .php riêng. Chạy php ten-tep.php; kiểm tra cú pháp bằng php -l ten-tep.php. Tự dự đoán kết quả trước khi chạy.

HTTP không tự nhớ người dùng

HTTP là giao thức không trạng thái: mỗi request cần đủ thông tin để server nhận diện ngữ cảnh. Session thường lưu dữ liệu phía server; trình duyệt giữ mã session trong cookie. Session không thay thế kiểm tra quyền.

<?php
session_start();
$_SESSION["user_id"] = 42;
echo "Đã thiết lập session trong môi trường thử nghiệm.";

Gọi session_start trước khi gửi HTML hoặc echo; nó cần gửi header. Mã ví dụ chỉ minh họa lưu giá trị, không xác thực người dùng.

Tách layout bằng require_once

include và require tải mã từ tệp khác. require dừng khi tệp bắt buộc không thể tải; require_once tránh nạp cùng tệp nhiều lần. Dùng __DIR__ để xác định đường dẫn tương đối từ chính tệp hiện tại.

<?php
// Giả sử partials/header.php tồn tại trong cùng thư mục.
$header = __DIR__ . "/partials/header.php";
if (is_file($header)) {
    require_once $header;
} else {
    echo "Tạo partials/header.php trước khi chạy trang đầy đủ.";
}

Ví dụ có kiểm tra để có thể chạy độc lập; khi header là bắt buộc trong ứng dụng, dùng require_once và xử lý lỗi tại môi trường phù hợp.

Luồng đăng nhập và truy cập dashboard

Sau khi đã kiểm tra mật khẩu bằng password_verify, tạo session và gọi session_regenerate_id(true) để đổi ID session. Dashboard phải kiểm tra session ở server trước khi xuất trang; dùng quyền phù hợp cho từng thao tác.

<?php
session_start();
// Ví dụ giả lập một kết quả xác thực, không dùng làm hệ thống đăng nhập.
$authenticated = false;
if ($authenticated) {
    session_regenerate_id(true);
    $_SESSION["user_id"] = 42;
}
if (!isset($_SESSION["user_id"])) {
    echo "Chưa đăng nhập";
}

Để chuyển hướng web dùng header("Location: login.php") và exit trước mọi đầu ra. Không gán authenticated = true cố định trong ứng dụng thật.

Cookie ghi nhớ tên tài khoản

Cookie lưu tại trình duyệt và được gửi theo request phù hợp. Ghi nhớ tài khoản chỉ nên lưu tên đăng nhập không nhạy cảm, không lưu mật khẩu. HttpOnly hạn chế JavaScript đọc cookie, SameSite giảm một số tình huống CSRF; Secure chỉ gửi qua HTTPS.

<?php
// Gọi trước khi có đầu ra. Ví dụ này không thiết lập cookie khi chạy CLI.
if (PHP_SAPI !== "cli") {
    setcookie("remembered_name", "An", [
        "expires" => time() + 86400 * 30,
        "path" => "/", "secure" => true,
        "httponly" => true, "samesite" => "Lax"
    ]);
}
echo "Cấu hình cookie ví dụ";

Cookie Secure cần HTTPS; khi thử bằng localhost HTTP, cookie có thể không được gửi như mong muốn. Cơ chế tự động đăng nhập an toàn cần token ngẫu nhiên, lưu hash, hết hạn và thu hồi, không đơn giản chỉ lưu tên.

Đọc và giải mã JSON

Dữ liệu tệp có thể không tồn tại, không đọc được hoặc bị hỏng. json_decode với JSON_THROW_ON_ERROR giúp phân biệt JSON lỗi; kiểm tra kiểu và cấu trúc trước khi xử lý.

<?php
$json = '[{"id":1,"name":"An"}]';
try {
    $students = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
    if (!is_array($students)) throw new UnexpectedValueException("Cần danh sách");
    echo $students[0]["name"]; // An
} catch (JsonException | UnexpectedValueException $e) {
    echo "Dữ liệu không hợp lệ";
}

Khi lấy từ file, kiểm tra file_get_contents trả false. Dùng dữ liệu mẫu, tránh tin nội dung tệp là hợp lệ chỉ vì định dạng JSON.

Ghi tệp và kiểm tra lỗi

file_put_contents trả số byte đã ghi hoặc false khi thất bại; FILE_APPEND thêm cuối file. LOCK_EX hỗ trợ khóa trong lúc ghi, nhưng không tự đảm bảo an toàn cho toàn bộ chu trình đọc–sửa–ghi.

<?php
$file = tempnam(sys_get_temp_dir(), "lesson18-");
if ($file === false) throw new RuntimeException("Không tạo được tệp thử");
try {
    $written = file_put_contents($file, "login success\n", FILE_APPEND | LOCK_EX);
    if ($written === false) throw new RuntimeException("Ghi thất bại");
    echo trim(file_get_contents($file)); // login success
} finally {
    unlink($file); // chỉ xóa tệp thử vừa tạo
}

Với ứng dụng đồng thời hoặc dữ liệu quan trọng, dùng cơ sở dữ liệu hay khóa bao trùm cả chu trình đọc–sửa–ghi; cần chiến lược khôi phục khi ghi lỗi.

Log an toàn và đăng xuất

Log nên ghi thời gian, hành động và kết quả đủ phục vụ chẩn đoán; tránh mật khẩu, token, session ID và nội dung nhạy cảm. Đăng xuất phải xóa session ở server và xử lý cookie theo cấu hình.

<?php
session_start();
$_SESSION = [];
session_destroy();
echo "Đã kết thúc session thử nghiệm";

Trong ứng dụng web thực tế cần xóa session cookie với cùng path/domain và thuộc tính tương ứng, rồi chuyển hướng. Kiểm tra CSRF cho các thao tác thay đổi trạng thái.

Bài tập theo lộ trình

  1. Tách partials/header.php và footer.php; dùng require_once trong login.php, dashboard.php và logout.php.
  2. Xây dựng đăng nhập dựa trên tài khoản mẫu được hash an toàn; đổi session ID sau đăng nhập, chặn truy cập dashboard khi chưa đăng nhập và chỉ ghi nhớ tên tài khoản khi được chọn.
  3. Ghi log sự kiện đăng nhập/đăng xuất không chứa bí mật; đọc và ghi danh sách sinh viên JSON, xử lý file không tồn tại, JSON lỗi và lỗi ghi.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
