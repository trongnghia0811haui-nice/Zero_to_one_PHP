Task Management: CRUD Task

Mục lục← Ngày 49Ngày 51 →

Mục tiêu và chuẩn bị

Thiết kế CRUD task theo project, kiểm tra ownership và thành viên, validate trạng thái/ưu tiên/deadline và bảo vệ web/API.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Task và phạm vi project

Mỗi task thuộc một project; nested route thể hiện phạm vi đó nhưng URL chỉ là dữ liệu đầu vào, không tự chứng minh task thuộc project.

GET    /projects/{project}/tasks
POST   /projects/{project}/tasks
GET    /projects/{project}/tasks/{task}
PUT    /projects/{project}/tasks/{task}
DELETE /projects/{project}/tasks/{task}

Kiểm tra task thuộc đúng project và quyền user trước khi đọc hoặc ghi; quyết định 403/404 theo hợp đồng.

Schema và quy tắc dữ liệu

Task có title, description, status, priority, due_date và project_id. Chỉ cho phép status/priority trong tập đã quy định; xử lý ngày null và múi giờ rõ ràng.

status: todo | in_progress | done
priority: low | medium | high
due_date: ngày hợp lệ, không trước hôm nay theo chính sách bài tập

Quy tắc không cho deadline quá khứ khi sửa có thể ngăn chỉnh task cũ: cần xác định chính sách riêng cho create/update.

Form Request

Dùng Form Request kiểm tra kiểu và quy tắc; user gửi project_id không được phép tự chuyển task sang project khác. Lấy project từ route đã kiểm tra quyền.

<?php
// Trong StoreTaskRequest::rules(); Rule đã import.
return [
    "title" => ["required", "string", "max:255"],
    "status" => ["required", Rule::in(["todo", "in_progress", "done"])],
    "priority" => ["required", Rule::in(["low", "medium", "high"])],
    "due_date" => ["nullable", "date", "after_or_equal:today"],
];

Ví dụ không bao gồm description, cần bổ sung theo schema. after_or_equal:today phụ thuộc múi giờ cấu hình của ứng dụng.

TaskPolicy

TaskPolicy xác định ai được xem, tạo, sửa và xóa task dựa trên project và vai trò/quan hệ thực tế. Middleware auth chỉ xác định danh tính; nó không cấp quyền truy cập mọi task.

Request → xác thực → tìm project/task đúng quan hệ → authorize → validate → ghi

Không rely vào ẩn nút, query param hay ID khó đoán. Test user ngoài project và task thuộc project khác.

Tạo task từ quan hệ

Sau khi đã kiểm tra quyền và validate, tạo task thông qua quan hệ project để project_id lấy từ project ở server thay vì client.

<?php
// Trong service sau authorization, $project và $data đã được xác định.
$task = $project->tasks()->create([
    "title" => $data["title"],
    "status" => $data["status"],
    "priority" => $data["priority"],
    "due_date" => $data["due_date"] ?? null,
]);

Quan hệ, fillable, migrations và database phải được cấu hình. Không gán dữ liệu request chưa được lọc.

Sửa và xóa

Không tin task ID đơn lẻ nếu route cũng chứa project ID. Giới hạn query theo project, kiểm tra policy, validate, rồi sửa hoặc xóa; xác định tác động với task_assignments.

Sai: tìm task toàn hệ thống rồi tin project_id client gửi.
Đúng: scope task theo project, authorize, validate và xử lý.

Dùng CSRF protection với form web; API dùng cơ chế xác thực và policy phù hợp. Xác nhận xóa không thay kiểm tra server.

Kiểm thử CRUD

Test tạo, đọc, sửa, xóa hợp lệ; sai status, ngày quá khứ, ID không tồn tại, project/task không khớp và người ngoài dự án. Kiểm tra trạng thái DB sau lỗi.

Case: task thuộc Project B, URL Project A → từ chối/404 theo hợp đồng
Case: client gửi project_id khác → không được chuyển task

Dùng database thử nghiệm. Kiểm tra email hoặc token nhạy cảm không xuất hiện trong response/log.

Bài tập theo lộ trình

  1. Tạo TaskService, StoreTaskRequest, UpdateTaskRequest, TaskController và API controller cho routes lồng project.
  2. Thực hiện thêm/sửa/xóa/chi tiết với title, description, status, priority, due_date; kiểm tra ngày và giá trị hợp lệ.
  3. Viết TaskPolicy và test user ngoài project, task thuộc project khác, project_id giả mạo và dữ liệu không thay đổi khi bị từ chối.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
