MySQL: Database, Table, Primary Key và Foreign Key

Mục lục← Ngày 20Ngày 22 →

Mục tiêu và chuẩn bị

Hiểu dữ liệu quan hệ, dựng bốn bảng cho ứng dụng sinh viên và giải thích quan hệ một-nhiều, nhiều-nhiều cùng tác động khi xóa dữ liệu.

Thực hành trên cơ sở dữ liệu MySQL thử nghiệm riêng, không dùng dữ liệu quan trọng. Chuẩn bị schema từ bài trước khi chạy các truy vấn liên quan.

Database và bảng

Database là nơi tổ chức dữ liệu; bảng gồm các dòng và cột. Mỗi dòng mô tả một thực thể hoặc quan hệ; kiểu cột và ràng buộc ngăn một phần dữ liệu không hợp lệ.

CREATE DATABASE student_management
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE student_management;

Chỉ tạo trên máy hoặc môi trường thử nghiệm bạn có quyền sử dụng. Tên database trong bài là ví dụ; lệnh CREATE có thể báo lỗi nếu tên đã tồn tại.

Khóa chính

PRIMARY KEY xác định duy nhất mỗi dòng và không cho phép NULL. AUTO_INCREMENT thường dùng để tạo khóa số, nhưng không đảm bảo các số liên tục hay phản ánh thứ tự nghiệp vụ.

CREATE TABLE classes (
  id INT AUTO_INCREMENT PRIMARY KEY,
  class_name VARCHAR(100) NOT NULL,
  description TEXT NULL
) ENGINE=InnoDB;

InnoDB hỗ trợ khóa ngoại. Chạy sau khi đã chọn đúng database thử nghiệm.

Khóa ngoại và quan hệ một-nhiều

Một lớp có thể có nhiều sinh viên; mỗi sinh viên trong mô hình này thuộc một lớp. Khóa ngoại students.class_id tham chiếu classes.id, giúp từ chối tham chiếu không tồn tại.

CREATE TABLE students (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(150) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  phone VARCHAR(30) NULL,
  class_id INT NOT NULL,
  FOREIGN KEY (class_id) REFERENCES classes(id)
    ON DELETE CASCADE
) ENGINE=InnoDB;

ON DELETE CASCADE sẽ xóa sinh viên khi lớp bị xóa, vì vậy chỉ dùng ở database thử nghiệm sau khi hiểu tác động. Hệ thống thật có thể chọn RESTRICT hoặc chiến lược khác.

Quan hệ nhiều-nhiều qua bảng trung gian

Một sinh viên học nhiều môn và một môn có nhiều sinh viên. Bảng scores liên kết students và subjects, đồng thời lưu điểm của từng cặp. UNIQUE ngăn trùng điểm cho cùng cặp nếu nghiệp vụ chỉ cho một bản ghi.

CREATE TABLE subjects (
  id INT AUTO_INCREMENT PRIMARY KEY,
  subject_name VARCHAR(150) NOT NULL,
  credits INT NOT NULL
) ENGINE=InnoDB;

CREATE TABLE scores (
  id INT AUTO_INCREMENT PRIMARY KEY,
  student_id INT NOT NULL,
  subject_id INT NOT NULL,
  score DECIMAL(4,2) NOT NULL,
  UNIQUE (student_id, subject_id),
  FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE CASCADE,
  FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE
) ENGINE=InnoDB;

Trường hợp nhiều lần thi cần mô hình hóa lần thi thay vì áp UNIQUE trên cặp. MySQL phiên bản được chọn cần hỗ trợ CHECK nếu bạn thêm ràng buộc khoảng điểm.

Sơ đồ ERD bằng chữ

ERD giúp nhìn thấy quan hệ trước khi viết truy vấn. Dấu 1 và N mô tả số lượng quan hệ; bảng scores liên kết hai phía và có thể chứa dữ liệu riêng của quan hệ.

classes 1 ─── N students
students 1 ─── N scores N ─── 1 subjects

Theo schema ví dụ, xóa một student hoặc subject sẽ xóa điểm liên quan do CASCADE. Chú ý tác động dây chuyền trước khi triển khai.

Thêm và kiểm tra dữ liệu mẫu

Chèn bản ghi lớp trước sinh viên vì khóa ngoại yêu cầu lớp đã tồn tại. Ví dụ giả định đây là database thử nghiệm mới và ID được gán như trong lệnh.

INSERT INTO classes (id, class_name) VALUES (1, 'CNTT 01');
INSERT INTO students (id, name, email, class_id)
VALUES (1, 'An', 'an@example.test', 1);
SELECT id, name, class_id FROM students WHERE id = 1;

Tránh chạy lại INSERT với cùng ID/email nếu chưa xử lý trùng. Email dùng miền ví dụ; không đưa dữ liệu cá nhân thật vào seed.

Kiểm tra toàn vẹn

Thử chèn khóa ngoại không tồn tại hoặc email trùng để quan sát lỗi, nhưng chỉ trên dữ liệu thử nghiệm. Sau khi lỗi xảy ra, kiểm tra DB vẫn giữ trạng thái mong đợi.

-- Ví dụ thất bại nếu class_id 999999 không tồn tại:
INSERT INTO students (name, email, class_id)
VALUES ('Thử lỗi', 'invalid@example.test', 999999);

Không tùy ý vô hiệu hóa FOREIGN_KEY_CHECKS để làm cho lệnh sai chạy qua. Lỗi là bằng chứng ràng buộc đang bảo vệ dữ liệu.

Bài tập theo lộ trình

  1. Tạo student_management với utf8mb4_unicode_ci và schema.sql cho classes, students, subjects, scores; chỉ chạy trên database thử nghiệm.
  2. Vẽ ERD có quan hệ classes–students 1-N và students–scores–subjects N-N; giải thích hệ quả của ON DELETE CASCADE.
  3. Viết seed.sql có ít nhất 3 lớp, 15 sinh viên, 5 môn và 30 điểm; kiểm tra khóa ngoại, email trùng và số lượng mỗi bảng.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
