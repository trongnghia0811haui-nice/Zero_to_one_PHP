Mục tiêu và chuẩn bị

Thiết kế các loại nhân viên có cách tính lương khác nhau, sử dụng interface và trait có chủ đích, tổ chức namespace/PSR-4 và chuẩn bị mini project quản lý nhân viên.

Lưu mỗi ví dụ vào một tệp .php riêng. Chạy php ten-tep.php; kiểm tra cú pháp bằng php -l ten-tep.php. Tự dự đoán kết quả trước khi chạy.

Kế thừa là gì?

Lớp con extends lớp cha để tái sử dụng hoặc chuyên biệt hóa hành vi. Quan hệ kế thừa nên thể hiện quan hệ là một loại; không dùng chỉ để tránh vài dòng lặp không liên quan.

<?php
class Employee {
    public function describe(): string { return "Nhân viên"; }
}
class FullTimeEmployee extends Employee {}
echo (new FullTimeEmployee())->describe(); // Nhân viên

Trong PHP, lớp con kế thừa từ một lớp cha. Thuộc tính private của lớp cha không thể truy cập trực tiếp từ lớp con.

Abstract class và phương thức trừu tượng

Abstract class không thể khởi tạo trực tiếp. Phương thức abstract xác định hợp đồng mà lớp con cụ thể phải triển khai; lớp cha vẫn có thể cung cấp hành vi chung.

<?php
abstract class Employee {
    abstract public function calculateSalary(): float;
}
class FullTimeEmployee extends Employee {
    public function calculateSalary(): float { return 1000.0; }
}
echo (new FullTimeEmployee())->calculateSalary(); // 1000

Giá trị trong ví dụ chỉ để minh họa cú pháp. Bài tập thực tế cần nhận và kiểm tra dữ liệu đầu vào thay vì dùng lương cố định.

Đa hình trong thực tế

Đa hình cho phép cùng một lời gọi phương thức được thực thi khác nhau tùy loại object. Hàm nhận kiểu lớp cha có thể xử lý các lớp con tuân thủ hợp đồng.

<?php
abstract class Employee { abstract public function salary(): float; }
class FullTime extends Employee {
    public function __construct(private float $base) {}
    public function salary(): float { return $this->base; }
}
class PartTime extends Employee {
    public function __construct(private int $hours, private float $rate) {}
    public function salary(): float { return $this->hours * $this->rate; }
}
$people = [new FullTime(1000), new PartTime(10, 50)];
$total = 0;
foreach ($people as $person) $total += $person->salary();
echo $total; // 1500

Thêm validation số giờ không âm, đơn giá và lương phù hợp khi xây dựng ứng dụng. Cách biểu diễn tiền cần được xác định rõ.

Interface — hợp đồng công khai

Interface định nghĩa phương thức mà các lớp triển khai phải cung cấp. Một lớp có thể implements nhiều interface; các phương thức trong interface là public.

<?php
interface Exportable {
    public function toArray(): array;
}
class Student implements Exportable {
    public function __construct(private string $name) {}
    public function toArray(): array { return ["name" => $this->name]; }
}
print_r((new Student("An"))->toArray());

Không đưa password hoặc dữ liệu nhạy cảm vào kết quả xuất chỉ vì chúng có trong object.

Trait — chia sẻ phương thức

Trait cho phép tái sử dụng mã trong nhiều class. Cần chú ý xung đột tên phương thức và tránh đưa quá nhiều trách nhiệm vào trait; trait không thay thế quan hệ kế thừa hay interface.

<?php
trait Timestampable {
    public function createdLabel(): string { return "Tạo lúc: " . $this->createdAt; }
}
class Record {
    use Timestampable;
    public function __construct(private string $createdAt) {}
}
echo (new Record("2026-01-01"))->createdLabel();

Trait này kỳ vọng class sử dụng nó có thuộc tính createdAt; ghi rõ yêu cầu đó và kiểm thử. Trong dự án lớn, cân nhắc thiết kế rõ ràng hơn thay vì phụ thuộc ngầm.

Namespace và PSR-4

Namespace tránh trùng tên class giữa các thư viện. PSR-4 ánh xạ tiền tố namespace tới thư mục; Composer tạo autoloader để tải class tương ứng. Tên và chữ hoa/thường cần khớp trên hệ thống phân biệt hoa thường.

<?php
namespace App\Models;
class Student {
    public function label(): string { return "Student"; }
}
echo (new Student())->label();

Ví dụ namespace có thể chạy độc lập. Trong dự án, lưu class ở app/Models/Student.php, cấu hình autoload trong composer.json rồi require vendor/autoload.php sau khi chạy composer dump-autoload.

Lưu JSON an toàn cho mini project

Phân tách dữ liệu lưu trữ và object để kiểm soát kiểu và validation. Khi đọc JSON, xử lý tệp thiếu, cấu trúc sai, ID trùng và lỗi ghi. Chỉ ghi vào tệp thử nghiệm do bạn tạo, không thao tác lên dữ liệu thật.

<?php
$employee = ["id" => 1, "type" => "full_time", "base" => 1000];
try {
    $json = json_encode($employee, JSON_THROW_ON_ERROR | JSON_UNESCAPED_UNICODE);
    $decoded = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
    echo $decoded["type"]; // full_time
} catch (JsonException $e) {
    echo "Dữ liệu JSON không hợp lệ";
}

Không lưu password plaintext hoặc dữ liệu nhạy cảm trong JSON. Nếu có nhiều tiến trình ghi đồng thời, dùng giải pháp có transaction hoặc khóa thích hợp.

Bài tập theo lộ trình

  1. Thiết kế abstract Employee có calculateSalary(): float, hai lớp FullTimeEmployee và PartTimeEmployee với quy tắc tính lương và kiểm tra dữ liệu rõ ràng.
  2. Tạo Exportable::toArray(), trait Timestampable và cấu hình PSR-4 cho App\Models; kiểm tra nạp class qua Composer.
  3. Hoàn thiện ứng dụng quản lý nhân viên lưu JSON: thêm, sửa, xóa, tìm tên, tính tổng lương bằng đa hình; xử lý ID trùng, tệp lỗi và dữ liệu không hợp lệ.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
