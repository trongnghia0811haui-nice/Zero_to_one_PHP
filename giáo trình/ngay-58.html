Mục tiêu và chuẩn bị

Chuẩn bị triển khai demo có kiểm soát, quản lý bí mật và xác minh luồng chính; hoàn thiện GitHub mà không công khai dữ liệu hoặc dịch vụ ngoài ý muốn.

Chuẩn bị bản ghi chú, sơ đồ và dự án thử nghiệm. Ví dụ minh họa phải được điều chỉnh theo yêu cầu và môi trường thực tế.

Xác định môi trường demo

Chọn môi trường phù hợp yêu cầu PHP/Laravel và MySQL, chi phí, giới hạn tài nguyên và quyền truy cập. Kiểm tra thời gian hỗ trợ và phiên bản theo tài liệu nhà cung cấp tại thời điểm sử dụng.

Local → môi trường staging/demo → kiểm tra → công khai khi được cho phép

Demo công khai và dịch vụ trả phí cần quyết định/ủy quyền phù hợp. Bài giảng không tự triển khai hay tạo tài khoản.

Cấu hình an toàn

Dùng biến môi trường hoặc secret manager cho APP_KEY và DB credentials; tắt debug và không commit .env. Kiểm tra document root trỏ public, HTTPS, quyền file và log.

APP_ENV=production
APP_DEBUG=false

Các giá trị chỉ là ví dụ. Không đưa APP_KEY, password hoặc token thật vào tài liệu, ảnh chụp và repository.

Database và migration

Dùng database demo tách khỏi dữ liệu cá nhân/production. Đọc lệnh trước khi chạy; migrate:fresh xóa bảng và không phù hợp nếu cần giữ dữ liệu. Chuẩn bị backup và rollback theo môi trường.

Kiểm tra database đích → sao lưu khi cần → migration phù hợp → kiểm tra dữ liệu

Không chạy lệnh phá hủy trên database chưa xác định. Cấp quyền database tối thiểu cần thiết cho ứng dụng.

Tài khoản demo

Tài khoản demo chỉ chứa dữ liệu không nhạy cảm; hạn chế quyền và vòng đời, quy định cách reset, đổi hoặc thu hồi. Đừng tái sử dụng mật khẩu thực hoặc cho phép demo chỉnh hệ thống thật.

Admin demo và Member demo → dataset cô lập → quyền/thời hạn rõ ràng

Cân nhắc tránh tài khoản admin công khai nếu không cần. Không đưa token hoặc mật khẩu thật vào repo.

Kiểm thử sau triển khai

Kiểm tra HTTPS, login, quyền, CRUD project/task, filter, dashboard và API bằng dữ liệu demo. Thử user không có quyền, endpoint không tồn tại, lỗi validation và trạng thái rỗng.

Luồng chính → trường hợp sai → phân quyền → log an toàn → kiểm tra lại

Không kết luận production-ready chỉ vì một trang mở được. Ghi lại URL, phiên bản, thời gian và kết quả kiểm thử thực tế.

GitHub và README

Xem git status/diff và lịch sử để tránh secret; viết README với chức năng, cài đặt, test, hạn chế, demo và ảnh dùng dữ liệu mẫu. Pin repo phù hợp nếu muốn.

git status
git diff
git log --oneline -5

Nếu secret đã từng commit, xóa ở commit mới không làm mất khỏi lịch sử; cần xử lý thu hồi và lịch sử theo quy trình phù hợp.

Theo dõi và khôi phục

Lập kế hoạch dừng demo, kiểm tra log, chi phí và xóa tài nguyên theo chính sách. Với lỗi triển khai, có phương án rollback an toàn và tránh để debug public.

Triệu chứng → log an toàn → xác định nguyên nhân → sửa/rollback → xác nhận lại

Không tự ý công khai hoặc thay đổi hệ thống production khi chưa được yêu cầu.

Bài tập theo lộ trình

  1. Chuẩn bị và triển khai demo Task Management lên môi trường được phép; tắt debug và dùng dữ liệu mẫu cô lập.
  2. Kiểm thử login, project/task, lọc, dashboard và API với user có/không có quyền; ghi kết quả thực tế.
  3. Rà soát GitHub/README, pin dự án phù hợp và chỉ chia sẻ URL sau khi kiểm tra secret, quyền và chi phí.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.

Tham khảo MySQL Manual và PHP Manual, chọn đúng phiên bản đang dùng.
