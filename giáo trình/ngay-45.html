Task Management: Khởi tạo Laravel, Migration và dữ liệu mẫu

Mục tiêu và chuẩn bị

Tạo dự án phát triển, cấu hình database thử nghiệm, xây dựng migration và model theo ERD; chuẩn bị dữ liệu seed mà không làm mất dữ liệu ngoài phạm vi.

Chuẩn bị bản ghi chú, sơ đồ và dự án thử nghiệm. Ví dụ minh họa phải được điều chỉnh theo yêu cầu và môi trường thực tế.

Khởi tạo dự án

Dùng Composer tạo ứng dụng Laravel vào thư mục mới. Kiểm tra PHP, Composer, extension và phiên bản Laravel tương thích; không ghi đè dự án hoặc cấu hình có sẵn.

php -v
composer -V
composer create-project laravel/laravel task-management-laravel
cd task-management-laravel

Chọn phiên bản cụ thể nếu cần tái lập kết quả. Không tự push repository hay triển khai; các thao tác công khai cần được cho phép.

Cấu hình môi trường

.env chứa cấu hình môi trường; .env.example chỉ chứa placeholder. Dùng DB thử nghiệm riêng và tài khoản quyền vừa đủ; APP_KEY và mật khẩu không được commit.

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=YOUR_TEST_DATABASE
DB_USERNAME=YOUR_DB_USER
DB_PASSWORD=YOUR_DB_PASSWORD

Đây là mẫu, không phải thông tin kết nối thật. Xác nhận database mà ứng dụng đang dùng trước khi chạy bất kỳ migration ghi dữ liệu nào.

Migration cho bảng project

Tạo bảng users trước projects; khóa owner_id tham chiếu users. Chọn hành vi khi xóa user theo nghiệp vụ thay vì tự mặc định cascade.

<?php
// Trong migration projects::up() sau khi import Schema và Blueprint.
Schema::create("projects", function (Blueprint $table) {
    $table->id();
    $table->string("name");
    $table->text("description")->nullable();
    $table->foreignId("owner_id")->constrained("users")->restrictOnDelete();
    $table->timestamps();
});

Ví dụ chọn restrictOnDelete để tránh vô tình xóa chủ dự án. Nếu sản phẩm có quy tắc khác, ghi rõ quyết định và kiểm thử.

Bảng trung gian

project_members cần khóa tới project, user và UNIQUE(project_id,user_id); task_assignments cần UNIQUE(task_id,user_id). Foreign key phải trỏ bảng được tạo trước.

<?php
// Trong migration project_members::up().
Schema::create("project_members", function (Blueprint $table) {
    $table->id();
    $table->foreignId("project_id")->constrained("projects")->cascadeOnDelete();
    $table->foreignId("user_id")->constrained("users")->cascadeOnDelete();
    $table->unique(["project_id", "user_id"]);
    $table->timestamps();
});

Cascade là quyết định có tác động dữ liệu. Hai khóa ngoại không tự xác minh user được giao task có thuộc project tương ứng.

Model, factory và seeder

Model khai báo quan hệ và trường được mass assign. Factory tạo dữ liệu giả; seeder dựng một tập quan hệ hợp lệ. Dùng mật khẩu demo được hash, không dùng thông tin đăng nhập thật.

php artisan make:model Project -m
php artisan make:factory ProjectFactory --model=Project
php artisan make:seeder DemoSeeder

Lệnh tạo file; kiểm tra tên file chưa tồn tại. Cách dùng command có thể thay đổi theo phiên bản Laravel, xem --help.

Kiểm tra thứ tự và số lượng

Sau migrate và seed trên database test, kiểm tra đủ quan hệ, khóa duy nhất và số lượng mẫu: 1 admin, 5 member, 3 project, 20 task. Ghi lại tài khoản demo bằng thông tin không nhạy cảm.

SELECT COUNT(*) FROM users;
SELECT COUNT(*) FROM projects;
SELECT COUNT(*) FROM tasks;

Kiểm tra owner và assignment thuộc đúng project, không chỉ đếm dòng. Không đưa mật khẩu demo dùng chung cho production.

Cảnh báo migrate:fresh

migrate:fresh --seed xóa toàn bộ bảng trong database kết nối rồi tạo lại. Chỉ chạy sau khi xác nhận chính xác database thử nghiệm có thể xóa; không chạy lên production hoặc dữ liệu cá nhân.

php artisan migrate:fresh --seed

Lệnh được liệt kê vì thuộc lộ trình; không tự động thực thi trong bài giảng. Có backup và phương án phục hồi cho bất kỳ dữ liệu quan trọng nào.

Quy trình nhánh

Tổ chức thay đổi thành các phần nhỏ, kiểm tra git status và diff trước khi commit; sử dụng nhánh feature theo quy ước nhóm. Tránh đưa .env và file nhạy cảm vào repo.

git status
git diff
git switch -c feature/project-schema

Tạo nhánh và commit chỉ khi phù hợp kế hoạch làm việc; không tự push, public hoặc deploy nếu chưa được cho phép.

Bài tập theo lộ trình

  1. Tạo project Laravel trong thư mục mới, cấu hình DB test và cấu trúc cần thiết; giữ bí mật khỏi Git.
  2. Viết 5 migration, model, relationships, factory và seeder cho 1 admin, 5 member, 3 project, 20 task; xác minh quan hệ.
  3. Chỉ trên DB test có thể xóa: chạy migrate:fresh --seed, kiểm tra trạng thái, số lượng và dữ liệu; áp dụng nhánh feature và tài liệu hóa môi trường.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
