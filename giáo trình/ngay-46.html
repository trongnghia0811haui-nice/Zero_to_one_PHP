Mục tiêu và chuẩn bị

Hoàn thiện luồng xác thực web và API, bảo vệ mật khẩu, giới hạn thử sai và kiểm thử session, token và trường hợp bị từ chối.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Thiết kế luồng xác thực

Đăng ký tạo user sau validation; đăng nhập xác minh thông tin và thiết lập phiên; đăng xuất vô hiệu session hoặc thu hồi token tương ứng. Tài khoản bị khóa phải bị từ chối theo chính sách trên mọi kênh.

GET /register → form
POST /register → tạo tài khoản
POST /login → xác thực
POST /logout → kết thúc phiên
GET /profile → xem hồ sơ

Xác thực danh tính khác kiểm tra quyền. Các route thay đổi trạng thái cần cơ chế bảo vệ CSRF khi dùng cookie/session.

Đăng ký và hash mật khẩu

Validate tên, email, mật khẩu và trường xác nhận; ràng buộc email unique trong database. Hash::make dùng thuật toán mật khẩu được cấu hình; không lưu plaintext hoặc tự xây dựng thuật toán hash.

<?php
// Trong controller sau validation; User và Hash đã import.
$user = User::create([
    "name" => $data["name"],
    "email" => $data["email"],
    "password" => Hash::make($data["password"]),
]);

Dùng validated data, cấu hình fillable chính xác và không cho client tự chọn role admin. Phải xử lý lỗi email trùng khi các request cạnh tranh.

Đăng nhập và giới hạn tần suất

Dùng Auth::attempt với credentials đã validate; sau thành công regenerate session ID. Áp dụng throttle theo chính sách tài khoản/IP và kiểm thử, tránh tiết lộ mật khẩu hoặc token vào log.

<?php
// Trong controller web Laravel.
if (Auth::attempt($credentials)) {
    $request->session()->regenerate();
    return redirect()->intended("/dashboard");
}
return back()->withErrors(["email" => "Thông tin đăng nhập không đúng."]);

Ví dụ cần import Auth và request hợp lệ. Throttle không thay thế xác thực đa yếu tố hoặc các biện pháp khác khi hệ thống yêu cầu.

Đổi mật khẩu và đăng xuất

Xác minh mật khẩu cũ trước khi đổi, validate mật khẩu mới và hash. Khi đăng xuất web, logout, invalidate session và regenerate CSRF token; quyết định chính sách thu hồi các phiên hoặc token khác.

<?php
// Trong controller web sau khi kiểm tra password hiện tại.
Auth::logout();
$request->session()->invalidate();
$request->session()->regenerateToken();

Đoạn code minh họa logout, không bao gồm đổi mật khẩu. Không đưa mật khẩu cũ hoặc mới vào flash input.

API Sanctum

API có thể cấp token sau khi xác thực hợp lệ; /api/me yêu cầu xác thực; logout thu hồi token theo hợp đồng. Gửi token qua header Authorization, không đưa vào URL.

POST /api/register
POST /api/login
POST /api/logout
GET  /api/me
Authorization: Bearer YOUR_ACCESS_TOKEN

Sanctum phải được cài và cấu hình theo phiên bản Laravel. Token có thể có abilities nhưng vẫn cần policy để kiểm tra quyền trên từng project.

Các tình huống lỗi

Kiểm thử email sai, password sai, user bị khóa, dữ liệu trùng, token bị thu hồi và request không có token. Phản hồi nên nhất quán và không tiết lộ cấu hình nội bộ.

Sai credentials → thông báo chung
Thiếu hoặc sai token → 401 theo hợp đồng
Token hợp lệ nhưng thiếu quyền → 403
Dữ liệu không hợp lệ → 422

Rate limit và mã lỗi có thể cấu hình theo hợp đồng; kiểm tra thực tế bằng feature test và Postman với tài khoản thử nghiệm.

Bảo vệ bí mật trong quá trình test

Dùng biến môi trường cục bộ để giữ token Postman, không commit giá trị thật. Email gửi thử dùng mailer log hoặc công cụ bắt mail ở môi trường test; không gửi thư thật khi chưa được yêu cầu.

Ví dụ biến trong Postman: {{base_url}} và {{access_token}}

Không paste token thật vào README, log hoặc ảnh màn hình. Khi nghi ngờ lộ token, thu hồi theo quy trình của môi trường.

Bài tập theo lộ trình

  1. Hoàn thiện web register/login/logout/profile và đổi mật khẩu với kiểm tra mật khẩu cũ; kiểm thử luồng sai và tài khoản khóa.
  2. Áp dụng hash mật khẩu và throttle route login; không cho client tự cấp role admin, regenerate session sau login.
  3. Xây dựng /api/register, /api/login, /api/logout, /api/me bằng Sanctum; test token sai/đúng, abilities, logout và 401/403.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
