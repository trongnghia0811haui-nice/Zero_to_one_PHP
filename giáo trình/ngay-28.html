PHP MVC: Model, View, Controller và Routing

Mục lục← Ngày 27Ngày 29 →

Mục tiêu và chuẩn bị

Phân chia trách nhiệm trong một ứng dụng PHP, hiểu luồng HTTP qua router, controller, model và view; dựng khung MVC nhỏ có GET/POST và xử lý 404.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

MVC giải quyết vấn đề gì?

Model quản lý dữ liệu và quy tắc liên quan; View trình bày; Controller nhận yêu cầu, điều phối và chọn response. MVC là cách phân chia trách nhiệm, không tự động giải quyết bảo mật hoặc xác thực.

Request → Router → Controller → Model
                         ↓
                    View → Response

Hãy thử vẽ luồng xem danh sách sinh viên. Controller có thể yêu cầu model lấy dữ liệu rồi chuyển dữ liệu tới view.

Cấu trúc thư mục đề xuất

Thư mục public chứa điểm vào web; code ứng dụng và cấu hình nên nằm ngoài document root khi triển khai. Việc tổ chức này giúp giảm khả năng truy cập trực tiếp vào các file không công khai.

public/index.php
app/Core/Router.php
app/Controllers/HomeController.php
app/Controllers/StudentController.php
app/Models/Student.php
app/Views/students/index.php
composer.json

Đây là cấu trúc tham khảo theo lộ trình; document root của máy chủ phải được cấu hình thực sự trỏ vào public.

Router ánh xạ method và path

Router chọn một handler từ phương thức HTTP và đường dẫn đã đăng ký. Dùng danh sách route rõ ràng, không chuyển trực tiếp dữ liệu URL thành tên class hay tên file bất kỳ.

<?php
$routes = [
    "GET" => ["/" => "home", "/students" => "student_index"],
    "POST" => ["/students" => "student_create"],
];
$method = "GET";
$path = "/students";
$handler = $routes[$method][$path] ?? null;
echo $handler ?? "404"; // student_index

Đây là bảng ánh xạ đơn giản, không tự gọi handler. Khi lấy URI thực tế, chỉ lấy path, xử lý mã hóa và triển khai 404/405 nhất quán.

Lấy đường dẫn từ request

REQUEST_URI có thể chứa query string; parse_url với PHP_URL_PATH lấy phần đường dẫn để route. Các giá trị request vẫn là đầu vào không tin cậy và cần kiểm tra.

<?php
$uri = "/students?q=An&page=2";
$path = parse_url($uri, PHP_URL_PATH);
echo $path; // /students

Đoạn này chỉ minh họa tách path. Nếu ứng dụng đặt dưới thư mục con hoặc dùng URL encoding, cần xác định quy tắc xử lý phù hợp.

Controller và Model

Controller điều phối luồng request; Model/repository chịu trách nhiệm truy cập và quy tắc dữ liệu. Hãy truyền PDO vào lớp cần dùng, không nối SQL từ tham số người dùng.

<?php
class StudentController {
    public function index(array $students): void {
        require __DIR__ . "/students-view.php";
    }
}
// Trong ứng dụng, controller nhận danh sách từ model/repository.

Ví dụ là một mảnh cấu trúc và cần file students-view.php ở cùng thư mục nếu gọi index. Đừng render tệp dựa trực tiếp vào đường dẫn do người dùng cung cấp.

View và escape HTML

View hiển thị dữ liệu đã được controller cung cấp. Escape dữ liệu không tin cậy theo ngữ cảnh HTML; tránh lặp lại logic truy vấn hoặc phân quyền chỉ ở giao diện.

<?php
$student = ["name" => "An & Bình"];
echo "<p>" . htmlspecialchars($student["name"], ENT_QUOTES, "UTF-8") . "</p>";
// <p>An &amp; Bình</p>

Nếu in vào thuộc tính, dùng dấu nháy và escape phù hợp. Quyền truy cập vẫn phải được kiểm tra ở server.

404, 405 và kiểm thử router

404 cho biết không tìm thấy route/tài nguyên; 405 phù hợp khi đường dẫn tồn tại nhưng phương thức không được hỗ trợ. Test cả trường hợp đúng và sai, không báo 200 cho mọi request.

<?php
$method = "GET"; $path = "/unknown";
$routes = ["GET" => ["/" => "home"]];
if (!isset($routes[$method][$path])) {
    http_response_code(404);
    echo "Không tìm thấy trang";
}

Đây là ví dụ 404 cơ bản. Muốn phân biệt 405 cần xác định path đã được đăng ký cho phương thức khác và trả header Allow phù hợp.

Bài tập theo lộ trình

  1. Dựng thư mục public/index.php, app/Core/Router.php, Controllers, Models và Views; cấu hình PSR-4 autoload bằng Composer.
  2. Viết Router cho GET/POST ánh xạ route đã đăng ký đến controller/action; kiểm thử path không tồn tại, phương thức sai và trả 404/405 phù hợp.
  3. Tạo HomeController và StudentController::index(), lấy danh sách từ model và render view, escape tên trong HTML.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
