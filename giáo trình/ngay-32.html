Laravel Routing: tham số, tên route và nhóm route

Mục lục← Ngày 31Ngày 33 →

Mục tiêu và chuẩn bị

Định nghĩa đường dẫn web, ràng buộc tham số, đặt tên route và tổ chức nhóm /admin; kiểm tra route được đăng ký và không nhầm route với phân quyền.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Route ánh xạ request

Route nối HTTP method và URI với closure hoặc controller. Laravel chọn route khớp theo phương thức và quy tắc đã khai báo. Dùng routes/web.php cho route web trong ví dụ.

<?php
use Illuminate\Support\Facades\Route;

Route::get("/welcome", function () {
    return "Xin chào";
});

Đoạn ví dụ đặt trong routes/web.php của dự án Laravel, không chạy độc lập bằng php file.php. Kiểm tra php artisan route:list.

Tham số bắt buộc

Tham số trong ngoặc nhọn được đưa vào handler. whereNumber giới hạn định dạng số, nhưng không thay thế kiểm tra bản ghi tồn tại hoặc quyền của người yêu cầu.

<?php
use Illuminate\Support\Facades\Route;

Route::get("/students/{id}", function (string $id) {
    return "Sinh viên #" . $id;
})->whereNumber("id");

Ví dụ chỉ trả chuỗi, không truy cập DB. Khi làm ứng dụng cần kiểm tra ID hợp lệ, tài nguyên tồn tại và user được phép xem.

Tham số tùy chọn

Thêm ? sau tên tham số và khai báo giá trị mặc định trong handler. Xác định rõ khi không có tham số thì trang sẽ hiển thị gì.

<?php
use Illuminate\Support\Facades\Route;

Route::get("/classes/{id?}", function (?string $id = null) {
    return $id === null ? "Tất cả lớp" : "Lớp #" . $id;
});

Tùy chọn không làm tham số tự an toàn; validate hoặc ràng buộc theo yêu cầu nghiệp vụ.

Named route

Đặt tên route để tạo URL theo tên, giúp tách liên kết khỏi đường dẫn vật lý. Khi route có tham số bắt buộc, phải cung cấp tham số khi gọi route().

<?php
use Illuminate\Support\Facades\Route;

Route::get("/students/{id}", function (string $id) {
    return "Sinh viên #" . $id;
})->whereNumber("id")->name("students.show");
// route("students.show", ["id" => 12]) tạo URL cho ID 12.

Đặt tên duy nhất trong ứng dụng. Nếu định nghĩa lại cùng method/path hoặc tên route, thứ tự đăng ký có thể gây nhầm lẫn.

Nhóm route và tiền tố

Route group chia sẻ prefix và name prefix cho các route. Prefix /admin chỉ tổ chức URL; muốn bảo vệ khu vực quản trị phải thêm middleware xác thực và kiểm tra quyền phía server.

<?php
use Illuminate\Support\Facades\Route;

Route::prefix("admin")->name("admin.")->group(function () {
    Route::get("/dashboard", fn () => "Dashboard")->name("dashboard");
    Route::get("/students", fn () => "Sinh viên")->name("students.index");
});

Ví dụ route được đặt tên admin.dashboard và admin.students.index. Nó chưa bảo vệ quyền; bổ sung middleware phù hợp trước khi dùng dữ liệu thật.

Kiểm tra route

Dùng route:list để xem method, URI, name và action; thử đường dẫn và method sai. Test route cũng cần kiểm tra authorization, response và trường hợp dữ liệu không tồn tại.

php artisan route:list
php artisan route:list --path=students

Các tùy chọn có thể khác theo phiên bản. Dùng php artisan route:list --help để xem trợ giúp của dự án.

Lỗi thường gặp

Tham số không khớp chữ số, route trùng lặp hoặc đặt route tổng quát trước route cụ thể có thể dẫn tới kết quả không mong muốn. Kiểm tra route:list và viết test thay vì đoán.

GET /students/12      → khớp whereNumber("id")
GET /students/abc     → không khớp ràng buộc số
GET /classes          → id là null

Kết quả chính xác còn phụ thuộc các route khác đã đăng ký. Không giả định thứ tự thực thi khi có route chồng lấn.

Bài tập theo lộ trình

  1. Tạo nhóm /admin với prefix tên admin. cho dashboard, students, classes; bổ sung middleware phù hợp khi có authentication.
  2. Định nghĩa /students/{id} có whereNumber và /classes/{id?}; test thiếu, sai và đúng định dạng.
  3. Đặt tên route, tạo URL bằng route() thay vì ghi cứng; dùng php artisan route:list kiểm tra tên, method và URI.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
