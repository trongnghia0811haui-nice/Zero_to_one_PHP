Laravel: Controller, Request và Response

Mục tiêu và chuẩn bị

Tổ chức route bằng controller, hiểu resource controller và vòng đời dữ liệu request/response; phân biệt đọc input với validate và kiểm tra quyền.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Controller trong Laravel

Controller gom các hành động liên quan thay vì đặt mọi logic trong route. Route dẫn tới controller, controller điều phối validation, model và response; business logic cần được tổ chức rõ khi tăng độ phức tạp.

<?php
use App\Http\Controllers\StudentController;
use Illuminate\Support\Facades\Route;

Route::get("/students", [StudentController::class, "index"]);

Đặt đoạn route trong routes/web.php. Class cần tồn tại và có phương thức index; truy cập dữ liệu vẫn phải kiểm tra quyền.

Tạo resource controller

Artisan có thể sinh controller theo quy ước resource với các phương thức CRUD phổ biến. Các phương thức sinh ra là khung ban đầu và cần được triển khai, không tự tạo ứng dụng CRUD hoàn chỉnh.

php artisan make:controller StudentController --resource
php artisan route:list

Dùng trong dự án Laravel thử nghiệm. Kiểm tra file đích chưa tồn tại trước khi sinh để tránh ghi đè công việc đang có.

Đăng ký Route::resource

Resource route tạo một nhóm route theo quy ước: index, create, store, show, edit, update, destroy. route:list giúp xác nhận method, URI và tên.

<?php
use App\Http\Controllers\StudentController;
use Illuminate\Support\Facades\Route;

Route::resource("students", StudentController::class);

Resource route không tự triển khai validation, database, phân quyền hoặc view. Dùng only hoặc except nếu ứng dụng không hỗ trợ mọi thao tác.

Request input và query

Request cung cấp input, query và only để đọc dữ liệu. input có thể nhận dữ liệu request nói chung; query đọc query string; only chọn tập khóa. Đọc dữ liệu không tự xác thực chúng.

<?php
use Illuminate\Http\Request;

function sample(Request $request): array {
    return [
        "keyword" => $request->query("q", ""),
        "name" => $request->input("name"),
        "fields" => $request->only(["name", "email"]),
    ];
}

Không sử dụng input trực tiếp để xây dựng câu SQL. Validate kiểu, chiều dài và quyền trước khi lưu hoặc truy vấn.

Response: view

Controller có thể trả view và truyền dữ liệu rõ ràng. Blade escape {{ }} mặc định, nhưng vẫn cần kiểm soát ngữ cảnh và không tùy ý sử dụng cú pháp HTML thô cho dữ liệu không tin cậy.

<?php
public function index() {
    return view("students.index", ["students" => []]);
}

Đây là phương thức minh họa, cần nằm trong class controller; students.index phải tương ứng với resources/views/students/index.blade.php.

Response: redirect và JSON

Sau thao tác POST, redirect kèm flash message giúp người dùng biết kết quả và hạn chế gửi lại khi tải trang. API có thể trả JSON và status code; tránh đưa bí mật hoặc dữ liệu không cần thiết.

<?php
// Đặt trong một phương thức controller sau khi lưu thành công.
return redirect()->route("students.index")->with("status", "Đã lưu");

// Ví dụ response khác trong một phương thức riêng:
// return response()->json(["message" => "Đã tạo"], 201);

Đây là hai dạng response thay thế, không đặt cả hai return nối tiếp trong cùng nhánh. Cần kiểm tra route đích tồn tại.

Validation và authorization

Dùng $request->validate hoặc Form Request để xác nhận dữ liệu; dùng policy/middleware cho quyền. Chỉ lấy các trường được phép, không gán hàng loạt request thô vào model.

<?php
use Illuminate\Http\Request;

function validateStudent(Request $request): array {
    return $request->validate([
        "name" => ["required", "string", "max:150"],
        "email" => ["required", "email", "max:255"],
    ]);
}

Ví dụ là hàm minh họa trong ứng dụng Laravel. Cần bổ sung quy tắc duy nhất và quyền theo nghiệp vụ; thông báo lỗi cho client phù hợp môi trường.

Bài tập theo lộ trình

  1. Tạo StudentController bằng --resource và đăng ký Route::resource; kiểm tra đủ route bằng route:list, không ghi đè file hiện có.
  2. Thực hành input, query và only; trả view, redirect kèm flash hoặc JSON trong các phương thức riêng, kiểm tra dữ liệu đầu vào.
  3. Tạo ClassController xử lý danh sách và chi tiết lớp; viết test đường dẫn đúng, không tìm thấy và truy cập không có quyền.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
