Laravel: Khởi tạo dự án và cấu trúc thư mục

Mục tiêu và chuẩn bị

Hiểu Laravel và Composer, tạo dự án trong môi trường học tập, cấu hình .env an toàn, đọc cấu trúc ứng dụng và triển khai route health cơ bản.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Laravel là gì?

Laravel là framework PHP cung cấp các thành phần như routing, controller, Blade, database và validation. Framework giúp tổ chức ứng dụng nhưng không thay thế việc hiểu HTTP, PHP, bảo mật và SQL.

Trình duyệt → route → controller → model/database → view hoặc JSON

PHP và Composer cần đáp ứng yêu cầu của phiên bản Laravel bạn chọn. Xem tài liệu chính thức và kiểm tra php -v, composer -V trước khi tạo dự án.

Tạo dự án bằng Composer

Composer tải mã nguồn và các thư viện theo composer.json và composer.lock. Tạo dự án vào thư mục mới, không ghi đè thư mục hiện có; dùng môi trường phát triển trên máy cá nhân.

composer create-project laravel/laravel student-app
cd student-app
php artisan --version
php artisan serve

Phiên bản mặc định có thể thay đổi theo thời gian. Muốn đồng nhất nhóm học, chọn phiên bản Laravel cụ thể tương thích PHP và ghi lại trong README.

artisan và server phát triển

Artisan là giao diện dòng lệnh của Laravel. serve khởi chạy server cho phát triển; mở URL được in trong terminal và nhấn Ctrl+C để dừng.

php artisan list
php artisan route:list
php artisan serve

Không dùng server phát triển như cấu hình production. Nếu thiếu PHP extension hoặc cổng đang bận, đọc thông báo lỗi và xử lý theo môi trường.

Các thư mục quan trọng

routes chứa khai báo route; app/Http chứa lớp xử lý HTTP; app/Models chứa model; database chứa migration/seed; resources/views chứa Blade; public là document root cho web server.

student-app/
  app/Http/
  app/Models/
  routes/web.php
  database/
  resources/views/
  public/index.php

Cấu trúc chi tiết thay đổi theo phiên bản và gói cài đặt. Không để toàn bộ thư mục dự án làm web root trên production.

Cấu hình .env

.env chứa cấu hình riêng môi trường. Không commit mật khẩu DB, API key hoặc APP_KEY; .env.example chỉ chứa giá trị mẫu không nhạy cảm. Sử dụng cơ chế cấu hình của Laravel và kiểm tra .gitignore.

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=student_management
DB_USERNAME=YOUR_DB_USER
DB_PASSWORD=YOUR_DB_PASSWORD

Các giá trị chỉ là minh họa. Dùng database thử nghiệm riêng và tài khoản quyền hạn phù hợp. Đừng chia sẻ tệp .env thật.

Route health không lộ bí mật

Route trả JSON về trạng thái ứng dụng; nếu kiểm tra database, chỉ trả trạng thái cần thiết và không gửi chi tiết exception ra client. Với hệ thống thật, cân nhắc phân quyền và tải do health check gây ra.

<?php
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Route;

Route::get("/health", function () {
    try {
        DB::connection()->getPdo();
        return response()->json(["app" => config("app.name"), "laravel" => app()->version(), "database" => "ok"]);
    } catch (Throwable $e) {
        return response()->json(["database" => "unavailable"], 503);
    }
});

Đặt trong routes/web.php. Ví dụ kiểm tra kết nối, không bảo đảm mọi truy vấn nghiệp vụ hoạt động; log lỗi ở server theo chính sách không lộ bí mật.

Kiểm tra và gỡ lỗi bước đầu

Đọc thông báo lỗi theo thứ tự: phiên bản PHP, extension, dependencies, khóa ứng dụng, cấu hình DB, route và log. Các lệnh xóa hoặc làm mới database chỉ dùng với DB thử nghiệm.

php -v
composer -V
php artisan about
php artisan route:list

Trong .env, APP_DEBUG chỉ nên bật ở môi trường phát triển. Trên production phải tắt debug và quản lý bí mật an toàn.

Bài tập theo lộ trình

  1. Tạo student-app bằng Composer, cấu hình database thử nghiệm và chạy php artisan serve; ghi lại phiên bản PHP và Laravel.
  2. Ghi chú chức năng routes, app/Http, app/Models, database, resources/views và public.
  3. Tạo route /health trả JSON tên ứng dụng, phiên bản Laravel và trạng thái kết nối DB; thử cả khi DB sẵn sàng và không sẵn sàng, không lộ mật khẩu hoặc lỗi nội bộ.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết

  • Tự giải thích từng khái niệm và chạy lại các ví dụ.
  • Hoàn thành bài tập và xử lý dữ liệu biên, dữ liệu sai.
  • So sánh kết quả thực tế với kết quả dự đoán và ghi lại lỗi.
