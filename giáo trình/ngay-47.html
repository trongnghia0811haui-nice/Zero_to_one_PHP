Task Management: Quản lý User và Phân quyền

Mục tiêu và chuẩn bị

Xây dựng kiểm soát quyền admin, owner và member; dùng middleware, policy và test request trực tiếp để ngăn truy cập trái phép.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Vai trò toàn hệ thống và quyền dự án

Admin là vai trò toàn hệ thống; owner và member là quan hệ với từng project. Tách hai khía cạnh để không vô tình cho mọi member quyền trên mọi dự án.

User A → Owner Project 1
User B → Member Project 1
User B → Không thuộc Project 2

Viết ma trận quyền cụ thể trước khi code. Theo lộ trình, owner/member được xem; owner/admin được sửa/xóa. Xác định rõ admin có quyền xem hay không trong hợp đồng sản phẩm.

Middleware admin

Middleware role có thể bảo vệ nhóm trang quản lý user. Kiểm tra user đã xác thực trước khi đọc role; từ chối request khi điều kiện không thỏa.

<?php
// Bên trong middleware đã import Closure và Request.
public function handle(Request $request, Closure $next) {
    if (!$request->user() || $request->user()->role !== "admin") {
        abort(403);
    }
    return $next($request);
}

Đây là phần phương thức trong middleware; chưa bao gồm khai báo class, đăng ký alias hoặc phân biệt 401/redirect khi chưa đăng nhập. Kết hợp auth theo cấu hình phiên bản.

Chống thay đổi role trái phép

Form quản lý user chỉ dành cho admin đã được phân quyền. Validate role trong danh sách cho phép, kiểm soát việc tự hạ quyền hoặc khóa tài khoản quản trị cuối cùng theo chính sách.

Các trường client có thể gửi không đồng nghĩa client được sửa.
role: chỉ endpoint quản trị được phép xử lý.

Không đưa role vào mass assignment của endpoint hồ sơ thông thường. Ghi log hành động quản trị phù hợp mà không lộ secret.

ProjectPolicy

Policy kiểm tra hành động trên một project cụ thể. Dùng truy vấn quan hệ thành viên và so sánh owner; không dựa vào project_id do client tự khai báo mà chưa kiểm tra.

<?php
// Đoạn trong ProjectPolicy; ví dụ role và quan hệ cần có trong model.
public function update(User $user, Project $project): bool {
    return $user->role === "admin" || $project->owner_id === $user->id;
}

Cần import User, Project và bảo đảm kiểu ID nhất quán. Quyết định admin có được xem mọi project trong policy view theo ma trận đã thống nhất.

TaskPolicy và quan hệ dự án

Để xem hay sửa task, xác định project thật của task rồi kiểm tra quyền của user trên project và quy tắc của task. Kiểm tra task thuộc project trong nested route, tránh thay project_id tùy tiện.

Yêu cầu /projects/{project}/tasks/{task}
→ tìm task thuộc đúng project
→ kiểm tra TaskPolicy trên task
→ thực hiện hành động nếu được phép

Không chỉ kiểm tra có token hoặc có role member; quyền cần gắn với tài nguyên cụ thể.

Kiểm thử quyền bằng nhiều tài khoản

Dùng ít nhất owner A, member B, user C ngoài project và admin; thử các URL/API trực tiếp, không dựa vào giao diện. Xác nhận status 403 hoặc 404 theo chính sách và dữ liệu không đổi.

Owner project A sửa project A → cho phép theo chính sách
User ngoài project A truy cập → từ chối
Member thường đổi role admin → từ chối

Xác minh session, token, pagination và bộ lọc không trả dữ liệu ngoài phạm vi. Test user bị khóa nếu hệ thống có chức năng này.

Ẩn nút không phải bảo mật

Blade @can hoặc @cannot giúp UI phù hợp quyền, nhưng controller/policy vẫn phải enforce khi nhận request. API cũng cần thực thi cùng chính sách.

@can('update', $project)
  <a href="{{ route('projects.edit', $project->id) }}">Sửa</a>
@endcan

Thử thay đổi ID trong URL và gửi POST trực tiếp để xác nhận server từ chối. Dùng database thử nghiệm.

Bài tập theo lộ trình

  1. Tạo middleware Admin và trang quản lý user chỉ admin truy cập; validate thay đổi role và khóa/mở tài khoản.
  2. Viết ProjectPolicy và TaskPolicy theo ma trận đã xác nhận; kiểm tra tài nguyên thuộc project đúng và quyền theo hành động.
  3. Test ít nhất hai tài khoản, gồm user ngoài dự án và người có quyền; kiểm tra 403 theo yêu cầu, response và dữ liệu không thay đổi.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
