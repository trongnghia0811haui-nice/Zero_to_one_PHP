Laravel Eloquent Relationships và N+1 Query

Mục lục← Ngày 36Ngày 38 →

Mục tiêu và chuẩn bị

Khai báo quan hệ một-nhiều, nhiều-nhiều và bảng trung gian scores; dùng eager loading và đo số query trước khi tối ưu.

Cần PHP CLI hoạt động theo Ngày 11. Ví dụ độc lập chạy bằng PHP CLI; đoạn Laravel, Blade hoặc SQL phải đặt vào dự án và môi trường tương ứng theo chú thích.

Quan hệ trong dữ liệu và model

Schema ngày trước có classes, students, subjects và scores. Một lớp có nhiều sinh viên; một sinh viên thuộc một lớp; quan hệ sinh viên–môn thông qua scores có thêm thuộc tính score.

classes 1 ── N students
students 1 ── N scores N ── 1 subjects

Tên model Classroom có thể cần protected $table = "classes" vì quy ước tên bảng mặc định không nhất thiết là classes.

hasMany và belongsTo

Classroom khai báo hasMany Student; Student khai báo belongsTo Classroom. Chỉ định rõ class_id khi tên model Classroom không khớp tên foreign key theo quy ước.

<?php
// Bên trong App\Models\Classroom:
public function students() {
    return $this->hasMany(Student::class, "class_id");
}

// Bên trong App\Models\Student:
public function classroom() {
    return $this->belongsTo(Classroom::class, "class_id");
}

Các phương thức nằm ở hai class riêng, cần import model tương ứng. Đảm bảo database có khóa ngoại và kiểu cột khớp.

belongsToMany với pivot scores

Vì bảng trung gian có tên scores thay vì tên mặc định, chỉ định bảng và khóa tường minh. withPivot cho phép đọc thêm cột score thông qua thuộc tính pivot.

<?php
// Bên trong model Student; import Subject.
public function subjects() {
    return $this->belongsToMany(Subject::class, "scores", "student_id", "subject_id")
        ->withPivot("score");
}

Nếu dùng đồng thời model Score và belongsToMany, thống nhất cách tạo/cập nhật bản ghi và các ràng buộc duy nhất để tránh dữ liệu không nhất quán.

Truy cập dữ liệu quan hệ

Sau khi tải student và subjects, mỗi subject có thể cung cấp pivot->score. Trong view, hiển thị dữ liệu bằng Blade escape và xác định trạng thái chưa có điểm.

@forelse ($student->subjects as $subject)
  <p>{{ $subject->subject_name }}: {{ $subject->pivot->score }}</p>
@empty
  <p>Chưa có điểm.</p>
@endforelse

Đây là đoạn Blade và cần biến $student có quan hệ subjects được định nghĩa; bảo vệ dữ liệu theo quyền người xem.

N+1 Query

N+1 xảy ra khi một truy vấn lấy N bản ghi rồi mỗi lần truy cập quan hệ chạy thêm truy vấn. Eager loading with tải quan hệ theo lô và thường giảm số query; đo thay vì chỉ dựa vào giả định.

<?php
// Trong controller hoặc service Laravel:
$students = Student::with(["classroom", "subjects"])->get();
foreach ($students as $student) {
    echo $student->classroom?->class_name;
}

Đây là đoạn phụ thuộc model và database. Optional access ?-> xử lý quan hệ null; escape tên khi đưa vào HTML.

Đếm query trong môi trường phát triển

Query log hoặc DB::listen có thể giúp quan sát số câu SQL. Chỉ bật cho phép thử nhỏ và tắt khi không cần; log có thể chứa dữ liệu nhạy cảm và tiêu thụ bộ nhớ.

<?php
use Illuminate\Support\Facades\DB;
DB::enableQueryLog();
$students = Student::with("classroom")->get();
foreach ($students as $student) { $student->classroom?->class_name; }
$count = count(DB::getQueryLog());
DB::disableQueryLog();
echo $count;

Ví dụ minh họa trong Laravel; khởi tạo dữ liệu giống nhau khi so sánh. Hãy xóa query log hoặc dùng kết nối riêng nếu cần đo nhiều lần.

Kiểm thử quan hệ

Tạo fixture gồm lớp có nhiều sinh viên, sinh viên không có môn và sinh viên có nhiều môn. Kiểm tra pivot score, số query, dữ liệu trả về và quyền truy cập.

Trường hợp 1: 1 lớp → nhiều sinh viên
Trường hợp 2: 1 sinh viên → nhiều môn
Trường hợp 3: sinh viên chưa có điểm
Trường hợp 4: user không có quyền xem

Không chỉ kiểm tra số query; phải xác nhận dữ liệu đúng và không rò rỉ bản ghi ngoài phạm vi được phép.

Bài tập theo lộ trình

  1. Định nghĩa Classroom hasMany Student và Student belongsTo Classroom với foreign key class_id; cấu hình tên bảng classes.
  2. Khai báo Student belongsToMany Subject qua scores với pivot score; hiển thị lớp và bảng điểm bằng eager loading.
  3. Đo số query với và không with() trên cùng dữ liệu; kiểm tra kết quả và các trường hợp quan hệ rỗng.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.
