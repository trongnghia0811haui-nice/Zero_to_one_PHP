Mục tiêu và chuẩn bị

Giải thích route, controller, Eloquent, auth, API và các quyết định trong dự án bằng bằng chứng code thật; luyện thuyết trình 5 phút.

Chuẩn bị bản ghi chú, sơ đồ và dự án thử nghiệm. Ví dụ minh họa phải được điều chỉnh theo yêu cầu và môi trường thực tế.

Nối các thành phần Laravel

Mô tả request đi qua route, middleware, controller, Form Request/policy, model và response. Thứ tự chi tiết phụ thuộc route và cách code của dự án; dùng ví dụ thật để giải thích.

Request → Route/Middleware → Controller → Model/DB → View hoặc JSON

Chỉ ra file thật trong dự án của bạn; không nói đã triển khai phần chưa làm.

Validation và authorization

Validation kiểm tra dữ liệu có hợp lệ; authorization kiểm tra người gọi có quyền hành động trên tài nguyên. Hai kiểm tra bổ sung nhau, và database constraint vẫn cần cho tính toàn vẹn.

Validation: status có thuộc tập cho phép?
Authorization: user có được sửa task này?
DB constraint: khóa ngoại và unique có hợp lệ?

Trình bày cả nhánh thiếu dữ liệu, user ngoài project và request cạnh tranh.

Auth web và API

Web thường dùng session/cookie; API có thể dùng token theo cấu hình. Giải thích cách đăng nhập, đổi session ID, bảo vệ token, logout/thu hồi và giới hạn tần suất.

Web: login → regenerate session → xác thực request
API: login → cấp token → auth middleware → policy

Không nói token tự giải quyết mọi authorization; không trình chiếu token thật trong demo.

REST và status code

Nêu endpoint, method, input, output và các trạng thái 200/201/401/403/404/422 theo hợp đồng đã triển khai. Giải thích sự khác nhau giữa lỗi validation và lỗi quyền.

GET /api/projects → 200 danh sách trong phạm vi quyền
POST /api/projects → 201 khi tạo thành công

Ví dụ chỉ là hợp đồng giả định; đối chiếu với route và test thực tế của dự án.

Eloquent relationships và N+1

Giải thích hasMany, belongsTo, belongsToMany và eager loading trên project/task. Nêu bằng chứng đo số query trước/sau nếu đã thực hiện; tránh khẳng định nhanh hơn khi chưa đo.

Project hasMany Task
Task belongsTo Project
Task belongsToMany User qua task_assignments

Kiểm tra tên bảng và khóa liên kết thực tế; eager load không thay scope quyền.

Trình bày dự án 5 phút

Tổ chức 5 phút theo bối cảnh, người dùng, chức năng chính, kiến trúc dữ liệu, bảo mật, một lỗi đã xử lý và kết quả kiểm thử. Dùng số liệu thực, không tự tạo thành tích.

1 phút: bài toán và vai trò
1 phút: kiến trúc và dữ liệu
1 phút: luồng chính
1 phút: bảo mật và kiểm thử
1 phút: bài học và hướng tiếp theo

Đây là phân bổ gợi ý, điều chỉnh theo dự án. Chuẩn bị demo dự phòng khi môi trường không hoạt động.

Nói về lỗi kỹ thuật

Chọn lỗi thật: điều kiện tạo N+1, điều kiện OR làm lộ phạm vi hoặc lỗi validation. Giải thích cách tái hiện, nguyên nhân, sửa và kết quả được kiểm tra.

Triệu chứng → Bước tái hiện → Nguyên nhân → Giải pháp → Bằng chứng

Không khẳng định đã triển khai hoặc đo được nếu chưa có. Ghi hạn chế và hướng kiểm tra còn lại.

Bài tập theo lộ trình

  1. Trả lời các câu hỏi Laravel/API/Auth theo lộ trình, liên hệ với file code thực tế và ví dụ cụ thể.
  2. Viết dàn ý 5 phút gồm bài toán, schema, policy, N+1 và hai lỗi đã xử lý; không tự tạo bằng chứng.
  3. Trình bày hai lượt, canh giờ và ghi phản hồi; sửa phần khó hiểu hoặc chưa có bằng chứng.

Ghi đầu vào, kết quả mong đợi và thực tế; kiểm tra cả trường hợp rỗng và biên.

Tự kiểm tra và tổng kết
